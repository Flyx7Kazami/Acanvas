# acanvas

项目级本地创作白板，通过通用 Agent Skill 与 agent 协作。

用户在白板中导入图片、视频和文件，选择对象或区域并添加批注，将附件与指令发送到当前白板会话的需求队列。Agent 按顺序处理任务，把产物放回共享白板。

## 核心约定

- 同一项目共享素材、画布对象、布局及已提交批注。
- 每个白板会话拥有独立的聊天、草稿和任务队列；生成产物进入共享白板。
- 不同会话可并行处理需求；每个会话队列由一个执行者串行消费。
- 用户发送只保存需求；正在消费的 agent 在任务边界读取新增需求。队列为空后退出，后续通过口令继续。
- 新 agent 会话可显式接续已有白板会话，恢复时检查任务与已有产物。

## 变更追溯

1. 开始工作前检查 Git 状态，保留已有变更。
2. 以 `docs/PLAN.md` 中的阶段、需求编号和验收项组织实现；范围变化先更新方案。
3. 执行者记录相关测试命令、结果及限制；独立审查者进行验收。
4. 主智能体在验收通过后提交当前范围的变更。提交描述当前行为，并关联相应阶段或需求编号。
5. 阶段进度与验证记录统一维护在 `docs/PLAN.md`；提交历史提供代码和文档的版本追溯。

Git 管理项目源码、文档和必要验收材料。运行数据位于项目的 `.acanvas/`，采用任务、执行尝试、产物记录和一致备份追溯；该目录保持在 Git 跟踪范围之外。运行数据备份属于产品实现范围。
