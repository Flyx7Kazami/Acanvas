# Chatbox 引用与即时画布批注计划

日期：2026-10-08（Asia/Shanghai）。状态：捕获基础与完整交互已实施；原结果见[实施验证](CHATBOX_IMPLEMENTATION_VALIDATION.md)，正文引用和点位呈现已按[最新调整](INLINE_REFERENCES_POINT_ANCHOR_DESIGN.md)完成并[验收](INLINE_REFERENCES_POINT_ANCHOR_VALIDATION.md)。产品范围以本计划和[实施设计](CHATBOX_IMPLEMENTATION_DESIGN.md)为依据。

项目运行与后台截图保持宿主无关，任何 agent 都可通过统一 CLI/API 使用。草稿、队列和证据按明确的会话任务范围隔离，宿主对话绑定是可选的范围解析入口。剩余实施及项目 Chrome 入口见[实施设计](CHATBOX_IMPLEMENTATION_DESIGN.md)。

## 1. 目标与现状

用户通过 chatbox 组织一次需求：`@` 引用明确对象，画布批注指出具体位置并附评论。单击对象或框选多个对象时，chatbox 在正文光标处先显示浅色、带轻微阴影的独立素材预览；用户点击 chatbox 后，它们在原位置变成正式颜色的引用。批注可在画布任意位置建立，点编号直接显示在点击点，完成时立即保存截图、目标、坐标、邻近元素和适用的媒体位置。批注摘要位于 chatbox 顶部，沿用当前缩略图。Send 把正文、正式引用和批注编成一条可读需求，同时保存结构化任务快照。

这里的“全画布”是标记工具的作用范围。未发送批注归当前会话任务范围的草稿；发送后只在该任务历史中按需呈现，不形成跨会话的全局评论层。

当前 [Draft 与 TaskSnapshot](../../src/shared/types.ts) 保存正文、统一顺序的对象/任务引用、显式附件、批注和独立捕获现场；[发送事务](../../src/server/service.ts) 用 draft ID 处理重复提交。Annotate 支持任意位置，Markdown 保存实际文本/视觉锚点，音频使用独立截图证据字段。[旧批注设计](../ANNOTATION_DESIGN.md)与既有任务快照继续按已保存内容读取。

本计划影响 R02、R04、R05、R13 及 A02、A06、A07、A09。第一阶段的“一条消息”指 acanvas 的一条持久任务及其可读需求文本；当前 Send 尚未直接投递到 Codex 宿主对话。[宿主消息桥](CODEX_MESSAGE_BRIDGE_RESEARCH.md)继续单独验证，不能把本计划的本地发送描述为已完成宿主投递。

交互参照 [Lovart 的画布元素 `@` 引用](https://www.lovart.ai/docs/how-to-prompt/chat-tools)、[局部 Mark 进入输入框](https://www.lovart.ai/docs/edit-your-design/advanced-ai-editing)及[本机 Codex 浏览器批注输入调查](CODEX_MESSAGE_BRIDGE_RESEARCH.md)。借鉴交互与输入编排，不假定这些产品的内部存储或消息接口适用于 acanvas。

Codex 当前桌面端在保存浏览器评论时先保存最新目标锚点，随后立即截图，聊天发送时再组织评论与截图；它允许截图失败后保留文字。acanvas 本计划按用户要求把截图也纳入“完成批注”的条件，详见[调查时序](CODEX_MESSAGE_BRIDGE_RESEARCH.md#保存批注与截图的时序)。用户进一步明确截图在后台执行，采用受信宿主对同一页面截图、隐藏编辑浮层并保留标记的路径，具体源码依据、隔离原型与接口边界见[基础设计](CAPTURE_FOUNDATION_DESIGN.md)。当前 `videoFrameAt` 和 HTML 静态预览分别取得媒体帧或隔离内容画面，原页面捕获能力以[验证记录](CAPTURE_FOUNDATION_VALIDATION.md)为准；生产宿主通道继续按实际集成验收。

## 2. 对话框交互

### 对象引用

1. 单击对象或框选多对象更新当前选择，并在正文当前或最后有效光标处显示引用预览；初次使用位于正文末尾。每个对象各自显示缩略图和名称，多对象逐个显示。预览只反映当前选择，不写入草稿的正式引用集合；选择改变时随之更新。
2. 用户点击或通过 Tab 等键盘操作聚焦 chatbox 准备输入时，将预览框对应的对象 ID 按当时的选择顺序加入正式引用，并呈现正式颜色。输入 `@` 后可在 chatbox 中搜索并选择画布对象或当前会话任务范围内的已有任务，选择结果直接成为正式引用。重复引用同一对象只显示一次；同一资产的不同画布对象保持各自的 ID。新增任务引用在服务端验证任务范围，其他会话的历史保持隔离。
3. 已确认的引用保持在正文的插入位置，可单独移除；再次选择对象可以继续添加。文字编辑同步移动引用，键盘或跨范围选择可以删除引用与选中文字。Escape 可取消尚未确认的预览。若用户直接点击 Send，当前可见预览先转为正式引用，再随同一次发送提交，避免所见内容被遗漏。纯文本中的 `@名称` 不自动解析为对象身份。
4. 引用框保存稳定对象/任务 ID、正文插入位置、跨类型显示顺序和必要的来源信息，显示名称只用于阅读。删除、移动或重命名对象后，草稿和已发送任务按各自保存的 ID 与快照处理；已失效的草稿引用给出可移除或重新指定的入口。键盘、触屏、输入法、纯文本粘贴和焦点切换均保持正文可编辑。旧记录缺少位置时按正文末尾读取。

显式上传的文件继续走附件入口。对象 `@` 引用与文件附件分开保存；选中画布对象不再自动把同一资产添加为显式附件。历史任务使用现有 `taskIds` 数据关系，经统一 `@` 选择器加入 chatbox。

### 批注

1. 标记工具覆盖对象内部、对象间空白和跨对象区域。单点命中对象时保存该对象身份与内容内坐标；落在空白处保存画布世界坐标。框选完全包含在一个对象的内容区域内时保存对象内区域；只要越过对象边界，就保存画布世界区域：完全空白时目标对象为空，只跨一个对象边界时该对象进入场景证据，跨多个或混合媒体对象时各相交对象都仅作为场景证据。邻近元素不自动成为用户明确的 `@` 引用，也不由区域相交推断各媒体的内容时间。
2. 对象重叠时以当前可见顶层对象为初始目标，并允许在完成前改选目标。点批注编号中心直接映射实际点击点，评论框独立展开、避让和错开；平移、缩放及评论编辑保持点位置。标记与平移、对象拖动、文字选择、媒体定位使用明确的手势模式；极小单点仍有可操作的命中区。
3. 用户输入评论并完成本条批注时进入捕获状态。截图、目标与场景信息保存成功后，chatbox 顶部出现正式批注摘要、数量及现有缩略图；点击可回到该条评论并编辑或移除。捕获失败保留文字与选择，显示重试操作，该条保持未完成，Send 等待其完成或由用户明确移除。
4. 修改评论文字保留原捕获现场；修改目标、区域、时间点或时间段重新捕获。旧的异步截图结果按任务范围、草稿 ID、批注 ID 和本次编辑版本忽略。发送后默认画布不展示这些标记；查看该任务时只读投影当时的批注和缩略图。

## 3. 完成批注时冻结的证据

一次完成操作形成同一版本的批注记录：用户评论、明确目标、对象与资产 ID、对象当时的版本和几何、内容内位置、世界位置、视口变换、截图区域与截图资产 ID、邻近元素的 ID/层级/当时几何、捕获时间及来源标记。截图显示用户标记与足够的周边画面，固定浮层在实际采样帧退出；保存截图范围和坐标映射，便于后来解释截图中的位置。邻近集合依据截图范围内的实际 DOM 布局与可确认遮挡，未知透明度或圆角保留相交候选为参考证据并稳定排序，精度说明见[实施设计](CHATBOX_IMPLEMENTATION_DESIGN.md#4-后台捕获协议)。数量与图片字节按[基础接口资源边界](CAPTURE_FOUNDATION_DESIGN.md#4-持久模型与编辑语义)限制，超出部分记录数量；明确目标由用户标记或选择形成。当前测量覆盖小场景，规模性能继续实测。

截图字节通过本地服务保存为受任务草稿引用的证据资产。正文与场景证据分开标记来源：评论是用户输入；Markdown、HTML、邻近文字和截图中的内容是参考证据。批注完成的 UI 以截图和记录均保存成功为准。捕获以同一个渲染现场为单位记录目标与邻近对象版本/布局、未提交拖动预览、视口变换与滚动位置、适用的媒体时间/画面；应用可控状态在截图期间稳定，变化时有限重试或保留未完成状态。持续播放和动画以捕获帧为证据，用户选择时间、实际播放位置及代表帧时间分别保存，现场时间精度依据实际采样能力声明。普通对象版本只能覆盖已提交布局变化，不能代替视口、拖动预览或媒体状态的一致性检查。完成后对象移动、缩放或删除不改写捕获记录；对象 ID 用于定位现存目标，冻结的对象/资产内容用于还原当时场景。

| 内容 | 完成时记录的内容位置 |
| --- | --- |
| 图片、普通对象 | 对象 ID、资产 ID、对象内归一化点或区域、当时世界位置与截图。 |
| 画布空白或越过对象边界的区域 | 世界坐标点或区域、视口变换、截图；可完全不含对象，也可与单个或多个混合媒体对象相交。相交/邻近对象只作场景证据，除非用户另行 `@` 引用。 |
| 视频 | 原视频 ID、时点或起止时间、画面内位置、适用的代表帧与现场截图；播放头后来变化不改变记录。 |
| 音频 | 原音频 ID、整段/时点/起止时间、当时波形和时间选择的现场截图。现场截图使用独立证据字段，不复用仅供视频帧的旧字段。 |
| Markdown | 原资产 ID、内容内点或区域、滚动位置和现场截图；选中文字时额外保存引文及上下文、可识别的段落/块路径与文本偏移。记录是文本锚点还是视觉位置；重排后按所记录的精度解释原现场。 |
| HTML、GIF、通用文件 | 原资产/对象 ID、内容内可见位置和现场截图。HTML 的 DOM 位置仅通过现有受控预览通道在可验证时补充；动态状态及 GIF 当前帧以截图为证据，不宣称可恢复其运行状态。 |

当前 Markdown/HTML 的能力边界见[多模态画布设计](../MULTIMODAL_CANVAS_DESIGN.md)。若某类型无法取得所需现场截图或视觉位置，该类型的即时批注保持未完成、不可发送，并显示可重试的错误；相应类型也不能宣称通过本计划的完整验收。实现需补齐实际捕获路径，或在交付前明确调整该类型的支持范围。文本锚点和 DOM 位置只有在实际识别成功时保存，不以猜测值替代。

## 4. Send、任务与历史

正式引用、已完成批注和正文属于同一份会话草稿。Send 先完成必要的草稿保存和证据上传，再由本地服务以现有 draft revision、draft ID 和短事务生成一条任务。一次成功发送的 `TaskSnapshot` 保存原始正文、按用户顺序排列的对象引用、批注结构、截图资产及相关对象/资产的捕获时与发送时信息。任务历史使用发送时内容；队列中待领取任务的 Edit/Save edit 继续保持原任务 ID 与序号，并按编辑后的内容更新快照。

从该快照确定性生成一份可读消息：保留用户正文原文，在对应位置插入标为参考内容的引用短标记，随后列出引用来源详情、每条批注的用户评论、明确目标、位置/时间、邻近证据和截图引用。界面展示与 agent/CLI 读取同一份任务信息；图片以资产 ID 获取，持久文本不内嵌 base64。导入文档和画面文字标为参考内容，不改写为用户命令。重复点击、响应丢失或刷新后继续按 draft ID 核对已创建任务，不重复生成任务或截图。

新批注只在所属会话草稿与任务快照中可读，其他宿主对话不加载。历史项目批注记录继续按原任务读取；新流程不需要把批注另写为可跨会话浏览的项目评论。旧任务快照、队列编辑和来源引用保持可读。现有版本允许已保存的跨会话任务 ID 引用：新 `@` 选择器不展示它们，新建引用也不接受它们；旧未发送草稿和旧待领取任务进入编辑时，可原样保留并提交其中已保存的引用，界面标明其历史来源且允许移除，移除后不能作为新引用重新加入。服务仅按原草稿或原任务快照中的既有 ID 核对这一延续关系，不因编辑正文而拒绝旧任务，也不扩展到任意新任务 ID。证据资产随草稿、任务和历史引用管理；取消、替换或删除草稿时先核对引用归属，避免清理仍由任务使用的截图。

## 5. 实施顺序

1. **截图能力实测与交互状态稿**：在隔离项目中取得真实的整画布现场截图，覆盖图片、视频、音频、Markdown、隔离 HTML、GIF、通用文件卡片及标记叠层，明确各类型可捕获范围、失败原因和耗时。所有列入交付范围的类型都要找到可重复的现场捕获路径；缺失的类型保留为未完成实施项。同时验证正文内独立预览/正式引用、顶部批注摘要与缩略图、空白画布和多对象标记、任务历史投影，覆盖桌面、窄屏、键盘和减少动态效果。
2. **草稿与快照模型**：把对象引用从显式附件中分离，保存对象与历史任务引用的统一顺序；扩展批注目标、内容锚点和独立现场证据字段。沿用既有 revision、对象版本、任务主键及事务规则；保留旧任务读取路径。
3. **捕获路径**：在批注完成操作中取得截图和同一画面对应的目标/邻近状态，经本地服务保存；实现捕获中、失败重试、编辑后重新捕获与异步结果归属。分别验证图片、视频、音频、Markdown、HTML/GIF 可提供的证据。
4. **chatbox 与任务呈现**：接入对象点击/框选预览、聚焦确认与 `@` 选择；新增历史任务引用限定当前会话任务范围，旧草稿与旧任务编辑中未改变的历史引用按原保存记录继续可用。顶部批注区保留缩略图。Send 生成结构化快照与可读消息，队列、历史、CLI 和任务编辑按同一快照读取。
5. **兼容与验收**：在隔离项目中验证旧任务、两个独立会话、对象移动/删除、刷新、重复发送和响应丢失；记录截图体积、捕获耗时及各媒体实际能力。当前用户画板数据保持原样。

## 6. 验收标准

| 场景 | 必须成立的结果 |
| --- | --- |
| 引用确认 | 单击和多选在正文光标处为每个素材形成独立浅色阴影预览；聚焦后在原位置变正式颜色。预览更换或取消不进入草稿；直接 Send 包含当前可见预览。`@` 选择保存对象或历史任务 ID、正文位置与显示顺序；同资产不同对象可分别引用，刷新和队列编辑恢复位置。 |
| 任意位置 | 对象内点/区域、空白画布点/区域、只跨一个对象边界的区域、多对象及混合媒体区域都可完成、重开和发送；点编号中心位于实际点击点，评论框独立避让。平移、缩放和对象重叠后目标明确，区域相交及邻近对象不会自动成为引用或媒体时点。 |
| 即时捕获 | 点击完成后才确认截图与评论、目标版本、坐标和邻近证据已保存；在截图期间改变视口、邻近布局、未提交拖动预览、媒体时间或 Markdown 滚动时，结果仍来自同一渲染现场或重新捕获。完成后再改变对象位置或播放头，批注仍还原原现场；失败可重试，旧异步结果不会回填。 |
| 媒体定位 | 视频/音频时间点和区间、Markdown 内容内位置与适用的原文锚点、HTML/GIF 可见位置及通用文件卡片均有现场截图可读；任何类型截图或定位失败时保持未完成并提供重试，该类型不计为验收通过。 |
| 一次发送 | 正文、正式引用和批注进入同一条任务；可读消息与结构化快照顺序一致。重复提交、断线及响应丢失可按 draft ID 核对；CLI 可据对象/资产 ID 和捕获证据读取原场景。 |
| 草稿与历史 | 当前对话刷新恢复草稿与缩略图；另一对话不见未发送批注，也不能通过新 `@` 选择器搜索或新引用本对话的任务。发送后仅任务历史投影。待领取任务编辑保存原任务 ID；旧批注和任务仍可读取。旧未发送草稿及旧排队任务中已保存的跨会话任务引用，即使仅修改正文也能原样发送或 Save edit，移除后不能重新添加；删除对象后历史依据完整。 |
| 输入与布局 | 键盘、触屏、输入法、复制粘贴、焦点和删除操作可用；明暗主题、320px 窄屏和减少动态效果下，预览/正式引用、顶部批注与原有缩略图均清楚可操作。 |

本计划只定义 acanvas 内的消息和任务内容。Codex 宿主对话的自动投递继续以[消息桥调研](CODEX_MESSAGE_BRIDGE_RESEARCH.md)为依据，待真实集成后单独验收目标线程、一次投递与结果不明恢复。
