# 正文引用与点位标记调整

日期：2026-10-08（Asia/Shanghai）。状态：实施与源码验收完成，结果见[专项验证](INLINE_REFERENCES_POINT_ANCHOR_VALIDATION.md)。依据用户本轮两项调整，关联 R02、R04、R05 / A02、A06、A07、A09。原[完整交互设计](CHATBOX_IMPLEMENTATION_DESIGN.md)及[功能计划](CHATBOX_REFERENCES_ANNOTATION_PLAN.md)中的引用尾部布局由本方案更新。2026-10-09 的重复出现、正式外观与批注交互规则见[当前调整](ANNOTATION_REFERENCE_REFINEMENT_DESIGN.md)。

## 1. 正文中的独立引用

普通素材引用插入正文当前光标位置；画布选择导致输入失焦时使用最后有效光标，初次使用正文末尾。多个素材各形成一个独立预览或正式引用，按选择顺序排列。预览继续采用浅色阴影，真实用户进入输入区后在原位置确认；程序焦点仅恢复编辑，Escape 消费预览，移除保持消费状态，直接 Send 确认可见预览。

输入区采用轻量 contenteditable，正文文本和不可编辑的引用原子在同一排版流中。每个原子保留缩略图/类型、名称、稳定身份和移除入口。`@` 选择在当前查询位置插入引用。原生键盘、箭头、Backspace/Delete、跨引用选择删除、换行、IME 与纯文本粘贴共同维护文档；引用内容继续由服务解析来源，粘贴普通名称保持文字。

编辑器用文本与引用原子保存文档语义，完整 `beforeinput` 数据形成一次正文操作，同一原生批次消费一次。原生 DOM 提供显示与选择，批次结束后统一呈现规范文档；焦点、箭头和引用确认先保存最新选择。IME 在原生组合期间维护 DOM，提交后读取正文。正文空行、原生行块及光标占位按其各自语义处理。

空态沿用现有紧凑输入栏尺寸与外边距。多行、引用及附件状态按真实内容自适应高度，正文、每个引用与控件完整可见，输入栏和工具栏保持可操作的独立空间；内容态的高度依据排版几何验收。

`Draft.text` 与 `TaskSnapshot.userRequest.text` 保留原始纯正文，引用位置使用 `RequestReference.textOffset?: number`，以正文 UTF-16 索引定位插入点。服务在同一草稿 revision 事务校验身份、范围、顺序和位置：索引为安全整数、位于 0…text.length、满足 code-point 边界，引用按正文次序保存，同位置按数组顺序展开。当前规则允许同一对象／任务多次出现，来源集合继续去重，同资产不同对象各自呈现。

UI 内部以文本字符和引用原子表达完整编辑位置，序列化时计算纯正文偏移。文本插入/删除同步移动引用；删除原子保留周围正文，选择范围跨原子时一起删除选中的文字与引用。引用缺少位置的旧记录按正文尾部呈现，字段形状继续按既有记录读取；用户编辑后可保存明确位置。

共享 `referenceParts(text, order)` 负责按同一规则拆分正文，编辑器、任务正文及可读消息采用相同位置。消息中的引用插入带参考来源的短标记，后续保留真实身份与来源详情；原正文独立保存。队列编辑更新位置同时沿用已保存引用内容和批注证据，刷新恢复原位置，CLI 读取同一消息。

## 2. 点位上的编号标记

新点批注的持久世界点或对象内归一化点仍是唯一位置来源。App 将实际标记范围传给批注组件，点位编号中心映射到该点的屏幕坐标。编号保持现有 28px 外观与命中方式，20px 空间轮廓与截图标记继续使用真实点。

编号标记与评论框分别布局。点标记保持坐标，评论短评/编辑框在旁侧展示，独立进行视口避让和过渡；多个评论的文字框可以错开，各自编号继续锚定其原点。打开、关闭、输入、媒体选择和窗口变化均保持编号中心。

区域与既有 geometry 缺省批注保留其现有边界/历史语义。任务历史继续依据捕获现场读取点，新对象位置由明确 Locate 操作使用。截图采样浮层退出、完整归属、后台捕获和证据事务继续采用已验收链路。

## 3. 验收

使用隔离真实项目和项目管理 Chrome，验证正文前/中/后引用、两素材独立呈现、同位置/跨类型顺序、真实 caret 与 @、删除/选择/IME/纯文本粘贴/Unicode、新旧草稿、刷新与队列编辑，以及 UI/CLI 消息位置一致。

点位验证空白、对象内容及归一化位置，覆盖平移/缩放/DPR、明暗、320px、触屏、同点/邻近多评论、编辑展开与截图。实测点击坐标、编号中心及 PNG 标记映射。旧区域/评论呈现与捕获失败、取消、SSE/响应归属保留必要回归。

技术执行及执行验证由子智能体完成。独立干净上下文审查最终候选；主智能体记录实际结果、保护既有白板数据，并在相关验收通过后完成本地提交。
