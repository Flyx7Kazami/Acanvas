# 截图环境与捕获基础验证记录

日期：2026-10-08（Asia/Shanghai）。依据：[基础设计](CAPTURE_FOUNDATION_DESIGN.md)、[功能计划](CHATBOX_REFERENCES_ANNOTATION_PLAN.md)、[方案审查](CHATBOX_REFERENCES_ANNOTATION_REVIEW.md)。

## 1. 范围与状态

本轮完成第 1 项截图环境与媒体原型，以及第 2 项批注状态与捕获提交的验证。用户要求直接参考 Codex 源码，并将正式截图路径确定为后台执行。后台原型 20/20、Node 测试 72/72、类型检查和构建通过；独立代码、原型、证据与文档总验收 PASS，无未关闭 P0–P3 发现。

交付内容包括真实服务的捕获 API、CLI、前端 API helpers、隔离后台宿主原型、测试和证据。当前 chatbox UI 按已交付行为运行，引用交互与宿主截图接线继续由后续阶段实现。用户白板和现有服务在本轮测试中保持原样。

## 2. Codex 安装源码核对

本机安装为 `/Applications/ChatGPT.app`，包标识 `com.openai.codex`，版本 `26.1002.52244`、build `13536`。执行调研保存[源码事实记录](../evidence/chatbox-capture/codex-source-observations.json)，独立审查重新核对了安装信息与关键函数。

保存评论后，主进程关闭编辑浮层，并让原页面 preload 重新解析目标、保留标记；下一帧 ready 后调用同一页面的零参数 `webContents.capturePage()`，再裁切、缩放和编码。该后台宿主结构是本轮原型依据。acanvas 的版本归属、捕获时新视口及完整证据要求按自己的服务语义验证。

## 3. 截图环境与媒体

Chrome 154.0.8037.98 使用独立浏览器 context 和隔离真实 acanvas 项目。最终[后台报告](../evidence/chatbox-capture/background-report.json)及[宿主链路报告](../evidence/chatbox-capture/background-host-report.json)为 20/20 PASS，包含 6 项原页面媒体/映射检查和 14 项后台生命周期检查，12.38 秒、exit 0；执行细节见[原型观察](../evidence/chatbox-capture/CAPTURE_PROTOTYPE_OBSERVATIONS.md)。独立审查以独立输出目录复跑同脚本，20/20、后台 14/14、exit 0，并实际查看最终图片。

| 内容 | 实际验证 |
| --- | --- |
| 图片 | 原画布图片、邻近内容和标记进入同页截图。 |
| 视频 | 原播放器实际播放，截取其当前显示帧；截图前后播放位置分开记录。 |
| 音频 | 真实完整波形、实验时间选择进入混合媒体现场；另取得[现有范围控件](../evidence/chatbox-capture/actual-audio-range-control.png)的完整可读截图，覆盖两端握柄与起止读数。 |
| Markdown | 内部滚动 260px 后取得当前可见正文；滚动与视觉坐标保留。 |
| 隔离 HTML | 父页跨 origin 读取受到浏览器隔离，同页合成器取得实际动态画面；两个时点的像素不同。另记录静态重建对照，动态状态以原页面画面表达。 |
| GIF | 最多 7 次、总采样预算 1800ms 的变步采样验证真实 RGBA 帧变化。 |
| 通用文件 | 文件卡片随同现场保存，原文件继续引用其资产。 |
| 标记与布局 | 编辑浮层隐藏、标记保留；DPR 2 下以实际缩放 0.833、1、1.44 验证像素映射与局部出屏；实际图像比例包括 1 和 2。 |

后台完成动作经过隐藏浮层、下一帧、同 Page 合成器截图、后裁切/缩放、prepare、PNG 上传、GET 核对和 Send，任务保存同一捕获与截图身份。[最终混合媒体图](../evidence/chatbox-capture/background-capture.png)为 1024×575、125,501 字节。

| 一次完成操作中的阶段 | 本机样例耗时 |
| --- | --- |
| 同页截图与原 PNG 编码 | 158.1ms，合并测量。 |
| 解码、裁剪绘制、裁剪 PNG 编码 | 25.0ms、0.1ms、42.1ms。 |
| 预备、上传、查询 | 5.1ms、17.5ms、1.1ms。 |
| 同一资产 PUT 重复核对 | 1.4ms。 |
| 完成操作总耗时 | 296.0ms；一次布局变化经第二次捕获完成为 420.6ms。 |

这些值来自小场景的单次实测。后台原型第一次上传读取并忽略返回值后再 GET 核对结果；真实响应正文丢失与重启恢复由第 4 节服务测试单独验证。

生命周期验收覆盖能力不可用、视口改变、取消、目标版本改变、超时、一次及持续布局变化、预备后取消/导航/超时、上传中取消、真实导航，以及同文档 history/SSE 更新。上传取消用例先确认临时文件已写入 61,153 字节，再按服务版本使旧捕获失效；评论保留、当前版本为 2 且未完成。独立复验写入 61,117 字节后得到同一状态。有限重试和取消贯穿整个后台任务。

IAB 使用自有临时页面，通过 CUA `tab.screenshot()` 取得真实画面，单次 33ms、74,989 字节，DPR 2、1280×720。`getDisplayMedia`、`setCaptureHandleConfig` 和 `getCaptureHandle` 可见；共享请求等待来源选择，未取得完整授权交互证据。该截图证明 agent 工具的原页面能力，产品的批注完成动作仍需受信宿主通道。

共享标签页实验仅作为环境对照。自动选择来源的 Chrome 配置取得动态画面；设备仿真的 CSS 视口与实际标签页流曾出现尺寸比例不符，原型拒绝该映射，改用实际视口和实际图像尺寸。原生来源选择、取消及用户结束共享保持待测。[中间对照记录](../evidence/chatbox-capture/sharing-comparison-intermediate.json)包含实验断言失败，作为过程证据保留，整体结果依据最终后台报告。正式产品方向为后台宿主截图。

新增集成测试验证以下结果：

| 验收项 | 结果 |
| --- | --- |
| 持久版本与未完成状态 | 新批注捕获失败、上传取消和重启后保留评论、目标及未完成状态；省略字段或移除后重加同 ID 继续遵循新流程。 |
| 评论与目标编辑 | 评论修改保留原捕获；目标、区域、媒体选择和内容锚点改变产生新版本；迟到旧结果按版本拒绝。 |
| 幂等及重拍 | prepare、PNG 上传和结果查询对应同一捕获身份；明确重拍产生下一版本，重试响应丢失后恢复同一新版本。 |
| 响应核对 | 客户端丢弃已提交捕获与 Send 的响应正文，重启后核对为同一截图资产和同一任务。独立审查补测草稿保存响应正文丢失，重启后恢复 revision 与输入，未完成批注发送返回 `annotation_incomplete`。 |
| 文件与数据库中断 | 真实子进程在 PNG rename 后、SQLite 完成前退出 77；重启时资产尚未登记，GET 核对后完成原捕获与原资产，Send 成功。 |
| 多次捕获及删除 | 同一对象在两次捕获中保存各自的对象几何和呈现几何；对象删除后两套现场继续可发送。 |
| 发送事务 | 未完成状态和版本不匹配均拒绝发送，草稿与任务数量保持；CLI 与 UI 使用同一服务事务。 |
| 队列与历史 | 只改文字保留捕获与任务 ID/序号，改目标要求重新捕获；取消编辑恢复原草稿证据；旧批注按已有字段读取与编辑。 |
| 证据归属 | 状态、GET/HEAD/Range、封面、HTML 预览、CLI 及普通素材写入口遵循会话证据归属；新跨会话任务引用按范围处理，旧引用延续读取过滤对方新捕获证据。 |
| PNG 与资源边界 | 结构、CRC、deflate、完整结束块、像素行和尺寸通过核对；JPEG、无效数据、尺寸/映射错误及超限输入保留未完成状态。 |
| 媒体与坐标 | 点/区域与内容锚点持久保存；用户选择的媒体区间和实际播放位置分开记录。 |

捕获证据支持 PNG，编码上限 20 MiB、1600 万像素、单边 16384、解码 64 MiB；场景上限为 64 个对象、256 个资产，按层级和 ID 排序并保存省略数量。本轮性能测量覆盖 7 个对象的小场景，后续规模测量继续推进。
