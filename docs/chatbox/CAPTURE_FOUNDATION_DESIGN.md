# 截图环境与批注捕获基础验证

日期：2026-10-08（Asia/Shanghai）。状态：第 1、2 项基础验证完成；范围与结果见[验证记录](CAPTURE_FOUNDATION_VALIDATION.md)，生产交互及宿主接线按后续阶段推进。

依据：[功能计划](CHATBOX_REFERENCES_ANNOTATION_PLAN.md)、[方案审查](CHATBOX_REFERENCES_ANNOTATION_REVIEW.md)。本轮覆盖审查建议顺序的第 1、2 项，关联 R02、R04、R05、R13 / A02、A06、A07、A09。

## 1. 本轮范围

使用隔离项目验证原页面的截图能力，并在真实本地服务中实现和验证批注持久状态与捕获提交基础。当前 chatbox 的引用交互、标记工具与历史展示继续按已交付行为运行；新捕获基础通过明确的新字段及 API/CLI 使用。宿主消息投递按[消息桥调研](CODEX_MESSAGE_BRIDGE_RESEARCH.md)独立推进。

用户明确要求正式实现像 Codex 一样在后台完成截图。产品路径采用受信宿主控制的同页截图：完成批注后关闭编辑浮层、保留标记，宿主取得原页面画面，再后台保存捕获结果。原型以受控浏览器宿主的完整后台链路验证这一方向。Codex 内置浏览器的实际接线按公开或已授权的宿主能力单独实现。

截图实验比较本机 Chrome 与 Codex 内置浏览器。自动化工具的同页合成器截图用于测量原现场；网页标签页共享作为环境对照，记录 API、授权及来源限制。自动选择共享来源的测试证明测试配置下的媒体路径。服务端另开页面、DOM 重建、独立视频采样各有用途，原现场能力以原页面实测为依据。

## 2. Codex 当前安装源码依据

只读核对的安装为 `/Applications/ChatGPT.app`，标识 `com.openai.codex`，版本 `26.1002.52244`、build `13536`。具体函数与安装包内 UTF-16 位置见[源码事实记录](../evidence/chatbox-capture/codex-source-observations.json)。

保存批注的链路从 `browser-sidebar-comment-overlay-submit` 到主进程 `handleCommentOverlaySubmit`、`handleOverlaySubmit`：先保存评论与锚点并关闭编辑浮层，再调用 `captureSavedCommentScreenshot`。`prepare-comment-screenshot` 使 preload 重新解析目标并显示标记，下一次 `requestAnimationFrame` 返回区域和 marker。主进程随后对同一页面的 `webContents.capturePage()` 执行零参数截图，取得整页图像后用 `NativeImage` 裁切、缩放和编码，回填该评论。

当前源码采用全视口长边 1280，局部加 32px 留白后长边 1024；至少 10 条评论时，紧凑图使用 16px 留白及 768 长边。裁切比例使用实际图像尺寸和视口尺寸。acanvas 原型借鉴同页面宿主截图与浮层时序，像素映射以捕获现场的新视口为依据。

Codex 保存路径先保留文字，截图失败或一秒 ready 超时后可留下无图评论；普通文字编辑沿用已有图像。该 saved 路径以页面及评论 ID 匹配等待结果，完整编辑版本归属和保存后视口变化仍需 acanvas 按本轮标准检查。Codex 的 direct 捕获分支具有捕获后的页面、标签页与对话归属检查。源记录证明实现方式，媒体及动态现场能力由本轮隔离实测验收。

## 3. 截图原型

媒体矩阵包含图片、播放中的视频、音频波形与时间选择、已滚动 Markdown、跨 origin 隔离 HTML 与动态内容、GIF、通用文件卡片，以及标记和邻近元素。捕获布局保留标记、隐藏编辑浮层。记录实际图像尺寸、裁剪 CSS 矩形和世界坐标映射，覆盖 DPR、画布缩放、内部滚动及局部出屏。

分别记录可测的截图、编码、上传和重试耗时及图像字节数。返回已编码图像的合成器接口记录其组合耗时。持续动画以捕获帧为证据；应用可控的布局、视口及编辑状态在捕获期间稳定，变动触发有限重试，达到次数或总时限后保留输入并提供重试。用户选择的时间区间、实际播放位置和代表帧时间分别表达。

后台原型通过受信测试宿主绑定原页面、会话、草稿、批注和编辑版本，验证完成动作到服务提交的自动链路。共享对照核实用户手势、选择来源、取消、来源不符、共享结束及刷新后的状态。测试报告逐项区分实际操作、自动化配置、模拟错误和待测场景。

## 4. 持久模型与编辑语义

新流程批注显式携带 `captureState`，包含服务管理的捕获修订版本与 `incomplete | complete` 状态。新建时处于未完成状态；目标、区域、内容锚点或媒体选择改变时，服务递增版本并使证据失效。明确重新捕获也产生下一版本，评论文字修改沿用捕获。上传、重新捕获和刷新期间，未完成状态持续阻止发送。完成状态及捕获身份由服务核对，客户端通过普通草稿保存提交用户编辑。

每条 `AnnotationCapture` 独立保存目标及场景对象/资产快照、内容坐标、世界坐标、视口、媒体选择与实际现场位置、截图映射、来源和捕获时间。同一对象在两次捕获中具有各自的几何。点与区域具有明确几何；点的操作命中范围与持久坐标分别保存。相交及邻近对象表达场景证据，显式引用继续独立保存。

基础接口接受每次最多 64 个场景对象、256 个资产，按层级和对象 ID 排序；省略数量单独保存。PNG 编码上限为 20 MiB，像素上限为 1600 万，单边上限为 16384，解码上限为 64 MiB。本轮媒体测量为 7 个对象的小场景，上限表达资源边界，规模性能继续由后续实测确定。

已有批注按其既有字段读取与编辑。新字段缺省对应已交付流程；新捕获流程一旦建立，其状态由服务沿当前保存记录持续管理。队列正文编辑沿用捕获；目标编辑需要新版本捕获。取消队列编辑恢复原草稿及其证据引用。

## 5. 捕获提交与中断恢复

捕获身份采用现有会话、草稿、批注 ID 和编辑版本，数据库唯一约束保证一个已提交结果。预备操作先保存证据元数据与服务分配的截图资产 ID；字节上传使用独立通道。本轮证据使用 PNG，服务核对图像结构、尺寸和解码完整性。文件完整写入并同步后落到该捕获的固定位置，再以短事务登记证据资产、完成记录及批注状态。

结果查询用于恢复响应丢失。完整文件已落盘、完成事务尚待提交时，查询核对已保存元数据与文件后完成登记。部分上传保持未完成，可继续重新上传。重复提交先核对已保存结果；迟到版本及其他草稿/会话的结果由服务按身份拒绝。未引用文件继续保留，自动清理由后续生命周期工作处理。

刷新或上传取消后，如果预备记录尚未完成且原 PNG 已丢失，重新拍摄会得到新的时间与动态画面。明确重试操作核对当前版本并递增捕获修订，再提交新的现场；原预备记录保持可核对。重试响应丢失后读取已保存的当前版本，重复请求按旧版本核对，继续沿一个新的版本执行。

业务接口使用 `/api/sessions/:session/drafts/:draft/annotations/:annotation/captures/:version`：POST 预备、PUT `/content` 上传 PNG、GET 查询结果、POST `/retry` 明确重新捕获。`prepared | committed` 表达文件提交状态，批注的 `incomplete | complete` 表达可发送状态。输入包含目标、世界坐标、当前视口、实际像素映射、场景对象与资产、媒体位置及捕获时间；服务为结果分配捕获 ID 和截图资产 ID，并标明参考证据来源。

Send 事务统一核对当前新流程批注的完成状态、匹配版本、捕获归属及完整文件。UI 与 CLI 共用该接口。每条捕获随任务快照保存；目标后续移动或删除时，完整捕获继续可发送、可读取。显式对象引用仍按其自身发送规则处理。原有 draft ID 保证一份草稿产生一条任务，队列编辑保留任务 ID 与序号。

## 6. 证据归属

截图资产具有会话、草稿及捕获归属，项目普通素材继续共享。状态、资产候选、资产内容 GET/HEAD/Range、封面、HTML 预览及 CLI 读取遵循该归属。普通附件、画布对象、资源包及输出登记等写入口保留证据资产的专属用途。

历史任务引用也遵循证据归属：新建任务引用限定当前会话，已有草稿及队列任务中保存的跨会话引用按功能计划继续使用，保存移除后按当前草稿核对延续关系。历史延续读取保留旧任务内容，并按来源会话处理其中的新捕获记录及专属截图资产。

这些规则表达产品的任务范围。当前本地服务的项目 token 与会话参数属于现有信任模型，宿主身份认证的能力按当前实现声明。

## 7. 验收与交付

执行测试使用独立临时项目、自有素材和独立端口；用户 `.acanvas/` 与现有服务保持原样。保留可复现脚本、媒体截图、机器可读指标和中断恢复证据。

第 1 项逐类型报告截图范围、动态现场结果、耗时与环境边界。第 2 项覆盖捕获中/失败后重启、过期异步结果、评论与目标编辑、同对象多次捕获后删除、队列编辑提交/取消、跨会话读取、上传/保存/发送响应丢失、文件落盘到事务之间中断，以及旧任务回归。一次真实媒体截图通过新捕获接口提交并发送，贯通两项。

独立审查依据本轮范围、验收标准和最终变更报告逐项结果。计划和验证记录采用实际完成状态，相关验收通过后由主智能体完成本地 Git 提交。
