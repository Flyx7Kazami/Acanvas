# 批注与正文引用交互调整

日期：2026-10-09（Asia/Shanghai）。状态：实现、八项独立验收、最终回归与正式服务更新完成，结果见[专项验证](ANNOTATION_REFERENCE_REFINEMENT_VALIDATION.md)。依据用户八项调整，关联 R02、R04、R05 / A02、A06、A07、A09。当前基于已验收的 Canvas 同帧后台捕获与正文引用原子实现。

## 产品行为

1. 批注输入、缩略图条与后台保存过程移除 `Capture required`、捕获 `Retry` 和 `Capturing` 提示。内部证据完整性、有限自动恢复、取消与 Send 校验继续工作；真实失败保留评论，用户可打开评论并再次 Done。
2. 画布中的收起评论文字使用随主题变化的半透明底、适量内边距及圆角。显示与保存截图中的文字底一致，编号仍锚定原点。
3. 正式正文引用沿用预览的中性边框与背景，只将文字改为较深的主题正文色；显示名称保持原名，确认后的名称采用原名。输入 `@` 仍可检索素材或任务。
4. 同一素材或任务可在正文多次引用。每次出现都是独立编辑原子，其位置与顺序分别保存；删除一次出现保留其他出现。`order` 保存全部出现及 UTF-16 偏移，`objectIds/taskIds` 保存去重的来源集合，任务快照中的真实素材及对象集合继续共用。草稿 revision 事务、数组顺序与位置已经表达完整文档，无须新增持久身份字段。
5. 元素旁的选择工具移除 Mark/Annotate 与 Attach。全局 Mark、画布选择产生正文引用预览和 `@` 检索继续作为入口；移除、对齐、播放与缩放操作保留各自用途。
6. 全局 Mark 模式下，鼠标在可批注对象内容上移动时显示定位边框。命中使用当前已显示帧的层次、实际内容位置、遮挡与圆角；悬停和点击锁定使用同一函数。空白或跨元素区域形成画布批注。打开评论后目标保持固定，Target 下拉框移除；Redraw mark 重新选择目标。退出、平移、取消、离开画布与目标变化及时清理定位提示。
7. 评论编辑器按正文、媒体控件和页脚三部分布局。正文保留可输入的最小高度，媒体与页脚完整占据自身高度，窄屏及长正文通过布局/滚动保持操作可达，控件与正文区域相互分开。
8. 对象批注截图优先包含锁定对象的完整显示范围与标记，画布区域批注继续按所选范围取图。范围取自同步复制的已呈现 N 及该帧对象位置，复制发生在编码和网络请求之前。超出当前画面的部分按实际可见边界裁切，继续保留原对象、视口与裁剪元数据；捕获流程继续使用同帧像素。原对象后来移动、换帧或删除时，已复制证据保持原样。

## 实施边界

正文出现与来源集合分开校验：`order` 可重复来源，来源集合仍唯一；每个来源至少出现在 order 中，order 条目只能指向集合内来源。现有上限、顺序、完整 Unicode 边界、历史内容、会话归属与 Send 事务继续适用。UI 的 DOM host 与删除操作以各个原子的位置/局部身份区分出现，序列化保留所有出现；预览只在一次明确选择中消费。

半透明评论底属于画布内容，Canvas 绘制与实际 DOM 几何共用颜色和位置。Mark 悬停边框属于定位提示，打开评论时撤下；证据沿用已锁定目标。旧截图和历史快照持续读取既有字段。

截图范围选择使用已呈现层的完整绘制边界及实际 CSS 投影，结合标记范围后按 Canvas 和页面可见边界裁切。对象内部区域或媒体时间选择继续保留细节意图，图像提供整个对象的现场上下文。源 HTML DOM、脚本、视频和 GIF 始终来自原呈现帧。

## 验收与交付

使用独立临时项目验证八项要求，重点覆盖重复对象/任务、不同与相同文本偏移、一次删除、原生编辑/IME/Unicode、刷新、Send、队列编辑及 CLI 消息；高亮/目标同一性、遮挡/圆角/空白、平移/缩放/DPR1/2、320px 与触屏；音频/视频编辑框正文、媒体及 Done 的真实几何；评论底与保存 PNG 一致；完整对象截图及部分出屏裁切、旧 N 保留、取消与失败恢复。

技术执行与执行验证由子智能体完成；独立干净上下文审查最终变更。构建输出先放在独立目录，正式服务通过受控接口更新并核对公开业务内容。主智能体维护设计与实际结果，在相关验收通过后提交 Git。
