# Annotation 功能与交互设计草案

日期：2026-10-03（Asia/Shanghai）；更新：2026-10-04。状态：用户确认范围已实现并通过独立验收。跨素材区域、多视频等文中后续设计议题继续单独确认。

## 1. 已确认的产品定位

用户已确认：

- Annotation 是给素材下达的创作指令，随一次任务发送。
- 画布默认显示编号和简短评论；选中后展开全文。

核心关系：一条 annotation = 一组明确的素材/区域引用 + 一段创作指令 + 必要的媒体上下文。任务负责组织、发送和执行这些指令。

首版聚焦创作指令。长期讨论、回复线程、评论解决状态、成员通知和独立评论收件箱暂不进入范围。

## 2. 设计前问题与设计原则

设计前的实现把创建中的内存输入、持久草稿批注、任务快照和项目批注记录放在多条路径中处理。展示、只读、创建及任务编辑又共用一套输入控件，通过隐藏按钮和改变布局适配不同状态。功能测试通过，仍不足以证明视觉与交互模型合理。

本轮先明确状态与职责：

1. 一条指令有一个身份、一份明确的编辑归属，入口只是访问方式。
2. 画布负责表达“指令针对哪里”，对话框负责组织本次需求，队列负责查看发送内容及任务状态。
3. 常态浏览采用轻量短评；完整阅读和编辑在用户选择后出现。
4. 阅读与编辑共用内容、编号和视觉语言，按各自语义使用展示或输入控件。复用组件以职责清楚为前提。
5. 相机移动由用户平移、缩放及适配操作触发；界面不提供 Locate 按钮。点击、聚焦、切换批注和接近视口边缘保持画布位置。
6. 整个任务只有一个提交入口：新任务 Send，等待任务修改 Save edit。

## 3. 来源与编号

| 目标范围 | 用户表达 | 必须保存的上下文 |
| --- | --- | --- |
| 单个素材 | “保留这张图的光线” | 素材/对象身份及完整来源 |
| 素材局部 | “把这个区域改成木质” | 对象身份、对象内归一化区域 |
| 多个素材 | “结合这三张的色彩” | 明确的对象集合；每个成员分别可读取 |
| 画布区域 | “参考这个区域里的排布” | 世界坐标区域、明确的来源集合及区域参考快照 |

目标范围与媒体上下文分别表达。视频整段指令引用原视频；时点指令保存时点及对应帧；区间指令保存起止时间，可增加代表帧。只有用户选了局部范围才需要区域坐标，整段视频指令不强制附加某一帧或区域。

素材局部随所属对象移动；素材组的呈现锚点跟随成员集合；画布区域保持其世界坐标及明确来源，具有独立语义。已有世界区域不会被悄悄转换为素材组或对象局部。

编号在同一草稿/任务内保持稳定，在画布、对话框和任务详情中一致；编号用于定位，底层身份单独保存。复制为新任务时创建新的指令实例，保留来源关系。

显式附件和批注依赖分别保存。仅通过批注引用的图片保持为该批注的来源；用户额外附加的图片保持为显式附件，包括两者指向同一素材的情况。

需要在下一轮原型中单独验证跨素材区域的关联表达，以及多视频来源的逐项时点表达。现有记录继续可读，迁移方案在数据设计阶段明确。

## 4. 生命周期与权限

| 上下文 | 查看与修改 | 保存含义 |
| --- | --- | --- |
| 当前任务草稿 | 新建和已有批注均可编辑、移除、调整来源 | 有内容后自动保存到当前草稿，刷新可恢复；尚未发送任务 |
| 已排队任务 | 默认只读；点击任务 Edit 后建立编辑草稿 | Save edit 一次性更新原任务，保留任务 ID 和队列位置 |
| 正在执行或历史任务 | 查看当时的文字、来源和媒体上下文 | 后续反馈作为新需求；保留原执行依据 |

创建中的非空正文进入同一个持久草稿模型。空白创建项不产生草稿记录；将已有正文清空后，从草稿移除该条记录，当前空白输入暂留至结束编辑，避免形成空指令。

项目批注记录作为来源和归档保留。将既有记录用于新任务时创建新的草稿实例，编辑只影响该实例。发送后的任务快照保存本次指令及完整来源，项目记录可作为归档或复用来源；用户界面只编辑当前草稿，不同时维护两份可写正文。具体存储是否合并在技术设计阶段决定，已有记录保持可读。

任务 Edit 中所有批注变化属于编辑草稿。Cancel edit 丢弃本次任务修改；Save edit 更新任务。原有普通输入草稿在任务编辑结束后恢复。草稿保存失败时保留本地内容，并提供明确重试。

Send/Save edit 必须包含当前输入框的最新内容，并在有效草稿 revision 上提交。输入法组字尚未完成时保持输入状态；依赖素材尚未就绪时完成保存准备后再提交。冲突或保存失败时保留本地内容和原任务，明确解决冲突后再提交；服务端确认成功后才退出任务编辑。

发送新任务成功后进入新草稿，已发送批注通过任务查看；Save edit 或 Cancel edit 后恢复原普通草稿。两种结束方式均把焦点放回对话框，保留用户自己调整的画布视口。

## 5. 三种画布呈现状态

业务生命周期和视觉状态分别管理。

| 视觉状态 | 呈现 | 操作 |
| --- | --- | --- |
| 常态 | 编号 + 一行短评；长文省略 | 点击编号、短评或对话框标签，选择同一条批注 |
| 选中阅读 | 展开全文与必要的来源/视频信息 | 查看来源；历史任务保持只读 |
| 选中编辑 | 同一全文区域切换为输入状态 | 编辑当前可写草稿；阅读与输入切换保持外框位置和宽度 |

结构草图（表达层级，具体像素尺寸待视觉稿验证）：

```text
常态            [1] 保留冷色调，降低整体饱和度…

选中阅读        [1] 保留冷色调，降低整体饱和度。
                    人物肤色维持自然，背景减少红色。
                    [来源缩略图] [来源缩略图]

选中编辑        [1] 保留冷色调，降低整体饱和度。│
                    人物肤色维持自然，背景减少红色。

任务底部        Cancel edit                         Save edit
```

常态短评采用真实展示元素，避免将每条批注渲染成带禁用按钮的输入框。可写草稿中的标签或短评点击后直接进入选中编辑；只读任务展开为选中阅读。任一时刻只有一条激活，其余批注保持短评。进入任务 Edit 时保留当前选中的批注身份，并在同一全文区域切换为输入状态。

新建直接进入选中编辑。使用 Enter 换行、⌘/Ctrl+Enter 完成本条编辑、Escape 结束本条编辑；完成或 Escape 返回常态并保留草稿，局部完成只结束输入。局部使用 Done 完成编辑，任务发送仍由底部 Send/Save edit 承担。

## 6. 入口、空间与视口

- 对话框标签、画布编号和短评访问同一个 active annotation；切换入口不会创建第二个编辑器。
- 点击任何入口保持相机位置与缩放。界面不提供 Locate 按钮。当前激活批注在视口外时保持相机不动，并保留原入口焦点；用户通过已有的平移、缩放与适配操作访问该位置。
- 结束本条阅读或编辑后，焦点返回原标签或编号；原入口已消失时返回对话框。切换任务查看只切换展示上下文，当前草稿继续保存。
- 标记、短评、全文阅读和编辑器保持屏幕尺寸，通过一次画布坐标到屏幕坐标的换算跟随素材锚点。素材及区域轮廓随画布缩放，气泡和文字保持可读大小；chatbox 与工具栏同样保持屏幕尺寸。小窗口可采用只依赖视口宽度的尺寸上限，接近边缘时保持尺寸和方位，允许裁切，不自动翻转或避让。
- 默认短评布置在素材或素材组外侧，编号与短评第一行中心对齐。区域本身通过轮廓表达，不把正文压在图像上。
- 同源多条批注按照稳定顺序组织成紧凑短评列表。选择展开是一项明确的用户动作；展开位置、增长方向及密集布局须在视觉稿中统一验证。
- 视频时点属于指令内容。查看时保留时点标识；跳转到帧由明确操作触发，避免浏览批注时意外改变播放状态。
- 素材移除后，任务来源仍可从快照读取。显示来源状态并保留文字修改能力，避免把不存在的对象重新加入画布。

固定锚点、正文始终完整可见、完全不占用其他内容空间，在密集或边缘场景中无法同时保证。本方案优先保持稳定关系和可预测视口；用常态短评、单一全文展开及用户主动平移或缩放处理空间不足。本次采用状态稿的素材上方展开关系，阅读与编辑共用固定屏幕宽度区域；密集和边缘场景保持锚定，由用户手动平移或缩放访问。

## 7. 对话框与队列

- 对话框只承担本次需求的总指令、显式附件和 annotation 标签。标签可显示编号及短摘要，不再复制一份批注编辑区。
- 标签移除表示从本次需求移除这条指令，素材本身保留。
- 队列详情按 annotation 分组：编号 → 全部来源缩略图 → 指令正文。素材名称只在有必要的辅助信息中出现。
- 查看历史任务使用该任务发送时的快照；正在输入的草稿继续保留。
- 画布只展示当前工作上下文的批注：当前草稿，或明确查看的一个任务。所有历史记录不会混在同一画布视图中。

## 8. 视觉语言建议

- 沿用当前灰阶界面与原有 AnnotationBubble 编号气泡 icon，保留其形状与编号呈现。蓝色承担批注身份与激活反馈，正文使用正常文本色。
- 常态短评控制在一行，建议最大宽度 160–220px；字体建议 13–14px。省略的全文通过选中访问。
- 全文区域建议宽 320–360px，尺寸以屏幕坐标为准，画布缩放不会改变文本尺寸。阅读与编辑维持同一屏幕宽度；长内容在区域内可完整访问。
- 编号标记建议 20–24px，与第一行文字中心对齐，间距约 8px。
- 常态减少容器装饰；全文层仅用必要的弱底色表达激活关系。圆角、文字内边距和输入样式采用统一的产品规范。文本框聚焦时保持原底色、边框与阴影，和 chatbox 一样无额外 highlight；保留光标、文本选区和按钮的键盘焦点反馈。
- 默认状态不出现禁用的返回、发送按钮。可写与只读由任务上下文和明确的编辑入口表达。
- 短评与全文框的展开、收回采用约 260ms 的非线性过渡，宽高与锚点位置连续变化；快速反向从当前可见位置接续。同一任务的全文阅读与编辑切换保持完整呈现和同一组件身份；文字输入、平移缩放和普通聚焦保持既有布局行为，减少动态效果模式直接切换。Cancel edit 使用局部主题悬停反馈并保持命中区域稳定。

全文桌面宽度为 360px，小窗口只根据视口设置上限，平移或缩放不会改变宽度；其余视觉尺寸继续以完整状态体验评估。

## 9. 实现边界建议

后续重构应按职责拆分，而非继续在单一控件上累加条件：

- **批注数据**：目标集合、正文、媒体上下文和稳定身份。
- **任务草稿**：唯一可写来源；任务编辑草稿与普通草稿分别归属。
- **任务快照**：发送时的文字与依赖来源，承担执行与历史依据。
- **交互状态**：当前激活批注及阅读/编辑能力，按所属上下文判断权限。
- **呈现与位置**：标记、短评、全文阅读、输入控件共用视觉基础；位置计算只负责画布关系。
- **相机行为**：仅响应用户的平移、缩放和适配操作。

保留现有任务顺序、revision 条件写入和快照保护。已有缺少来源信息的记录保持可读，避免按视觉结果推测并改写历史数据。

## 10. 设计确认与实施顺序（记录）

本次确认范围已按以下流程完成；后续扩展继续分别确认范围。

1. 先确认本稿的生命周期、保存含义和三个视觉状态。
2. 制作低保真状态对照稿：新建、常态、选中阅读、任务编辑；额外放入多素材、视频、密集批注和边缘场景。
3. 在原型中走一遍完整任务：创建两条指令 → 发送 → 查看 → 修改一条 → Save edit → 重新查看。先确认视觉与交互，再确定实现范围。
4. 实现按上述职责一次性整理相关路径，更新对应测试。验收同时包含用户对状态稿的确认、真实交互和数据保存验证；自动化几何通过不能替代设计接受。

前一轮仅进行了调研与设计。2026-10-04 用户明确要求直接实现，并确认无输入焦点 highlight、取消 Locate、批注与素材共享画布缩放以及保留原 icon。确认范围进入实现；正式白板数据继续受既有隔离与服务规则保护。

## 13. 缩放策略调整（2026-10-04）

用户实际试用后选择保持标记与文字的屏幕尺寸。该决定替代本日较早的世界尺寸缩放方案；短评/阅读/编辑状态、持久草稿、无输入焦点高亮、取消 Locate 和原气泡 icon 均保留。素材与区域轮廓仍随画布缩放，组件锚点跟随素材，尺寸仅在真实视口大小改变时按界面上限调整。

该调整已通过聚焦与独立验证：0.5/1/1.5/2 倍画布缩放下，编号 28px、正文 13px、全文高度 160px 保持；全文宽度在桌面/390/320px 窗口分别为 360/310/240px。素材锚点换算与 8px 间距准确，已有保存与编辑行为保留。
