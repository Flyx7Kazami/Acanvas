# 首次加载、HTML 响应与播放中的画板性能

日期：2026-10-09（Asia/Shanghai）。状态：实现及分项独立验收完成，必跑业务用例已通过整轮或同候选定向复验，受控运行更新与两轮完整性对照完成。基于 `f3269b8`，对应 R02、R03、R04、R11、R12 / A01、A04、A06、A09、A13、A14。

用户确认本轮交付正文引用、首次加载、HTML 响应／滚轮与音视频播放性能修复。研究中发现的原生 smooth scroll 精确 DOM／像素配对限制单列；需要 CEF／Chromium 内核扩展的[原子捕获事务](NATIVE_ATOMIC_CAPTURE_EXTENSION_DESIGN.md)不纳入本次运行版本。

## 产品要求

首次打开与刷新时，图片、Markdown、音视频和 HTML 按各自准备完成的时点显示；多个页面同时连接仍能推进资源请求。HTML 的按钮、表单与原生输入及时反馈。在画板 HTML 上，普通滚轮／触控板双指滑动平移画板，Ctrl／Meta 滚轮与触控板捏合缩放画板。Markdown 正文及任务详情的内容滚动保持各自作用域。触屏 HTML 保留既有单指内容输入和控件作用域；空画板继续支持双触点缩放。

音频或视频播放并且 HTML 持续运行时，平移和缩放保持响应，沿用现有单项音视频播放规则。媒体的真实画面、时间、控件、文本与批注使用同一已呈现帧；Done 同步复制当前画板像素和元数据，随后后台编码及保存。播放、画质、DPR、输入和截图语义均属于验收内容。

## 根因与实现方向

HTML 客户端在采样及解码完成后等待 250ms 再采样，输入确认没有触发即时采样。独立正常 CEF 基线的原生点击处理通常为 2–10ms，客户端仍需等待下一轮配对帧。交互响应分别记录输入入队、原生处理、配对采样、传输／解码和画板呈现时间。原生采样暂停脚本及动画，以取得像素与语义配对；调度调整保持这一边界。原生 popup 组合在没有可见 popup 时仍解码、复制和重新编码 PNG，此时直接返回本轮原 PNG；可见 popup 继续完成实际组合。

视频每帧经过生产 Canvas 绘制／来源校验，再复制到私有内容纹理并再次校验。音频播放的逐帧绘制包含完整面板的 DOM 布局、文本与波形，并由 DOM 变更通知再次安排绘制。测量需要区分像素复制、GPU 回读、布局、文字绘制、场景合成和浏览器长任务。

冷启动同时包含静态素材请求、解码、控制面板首次绘制、view 注册和 HTML 实例准备。隔离项目的三个真实 App 页面，每页项目事件和 view 活性各占一个持续 HTTP/1.1 连接；新增业务请求排队 3508ms，实际网络耗时 1.3ms，关闭一页后约 8ms 完成。网络饥饿可以发生在素材、注册、HTML 创建、输入与采样请求。实际 Edge 存在三个项目页，但内置浏览器的独立连接池未完成同样诊断；隔离复现与实际页面归因分别声明。

浏览器每个 BoardApi 使用一个经过既有 cookie 认证的同源 WebSocket，承载项目事件及具体 view 活性；业务数据继续使用 HTTP 接口。服务器复用 Host／Origin／认证与完整 view 身份校验，确认订阅后才报告该 view 已连接；断线宽限、重连、取消订阅、页面离开和服务关闭分别清理原归属。消息采用有界类型结构，凭据保留在现有受保护渠道。

移除持续 HTTP 占用后，三页混合冷启动仍有资源排队。九个原生 HTML 的单实例打开耗时约 0.95–2.13 秒，整个项目的创建链却逐个等待实例完成，使后续创建总等待达到约 8 秒。创建采用短同步名额登记，已经登记的各实例独立启动，启动中的实例继续计入原有 view、项目和历史容量。登记前的在途创建按 owner 跟踪取消，view 离开与服务关闭覆盖准备和启动阶段；单实例输入与采样继续各自串行。

## 实现原则

生产者按来源和对象生命周期工作，视口移动保持既有资源。音频面板将 DOM 布局、文字几何和有限绘制指令按实际依赖缓存，动态波形和时钟逐帧更新；指令按原顺序在唯一私有 GPU Canvas 执行，包含祖先透明度、裁剪、可见性及前景内容。绘制接口采用有界类型和数值／字符串校验，私有 context 保留在实现内部。主题、字体、大小、内容、焦点、选择和动画结束驱动准确失效。每个已发布帧继续拥有私有像素和该帧元数据，异步迟到、取消、来源改变及污染来源保持现有处理。

面板等价验证分别比较相同 GPU 后端的即时绘制与缓存指令，以及当前 CPU helper 与原版本 CPU helper。GPU 与 CPU 的文字抗锯齿和纹理采样差异单列，来源 RGBA、绘制属性、分辨率、DPR 和播放帧率保持。帧快照始终复制实际已提交像素，来源校验逐帧执行。

HTML 输入、周期采样和尺寸变化采用同一明确调度，确认后的交互及时请求一致帧，在途工作合并，避免重复采样和相互覆盖。画板与任务详情按实际交互作用域路由滚动。

HTML 语义控件按输入回执协调本地编辑与源页面投影。待确认的编辑和组合输入保有本地值、选区及焦点；覆盖已接受输入的帧到达后，统一应用源页面的 canonical 状态。原生表单控件以首次默认值初始化，后续投影通过同一个协调入口执行。程序投影登记已知选区，真实用户的选区意图单独记录，重复 SelectAll 仍能传到源页面；画板像素帧继续正常发布。

客户端的真实焦点域决定焦点投影权。用户进入 HTML 交互域后，源页面的 Tab、脚本焦点和控件切换映射到该域；用户转到批注、正文输入或其他页面控件后，这些控件持有焦点，HTML 周期帧继续更新内容而保持该客户端归属。重新进入 HTML 时由真实指针／键盘／焦点动作取得交互权。该规则覆盖全部外部输入，不依赖具体批注 CSS、延时或对错误焦点的事后纠正。组合输入完成／取消、owner 退役与迟到回执仍遵循同一编辑生命周期。

原生 helper 的子进程登记按已知父进程逐层枚举，一层合并一次 `pgrep -P` 与 `ps -p`，只接纳请求过的 PID、可信父 PID 和本 helper 前缀。启动中的 owner、部分进程退出及回收路径沿用同一归属关系。具体 HTML renderer 的暖启动尾延迟另行记录，内部等待原因保持未知。

独立验收在 CSS transform 动画中两次复现元素语义位置与 PNG 实际位置相差 6–11px。源页面的 DOM／动画主线程与 compositor 独立动画时钟需要统一：项目 CEF 使用 `disable-threaded-animation`，保留原脚本暂停、时间线恢复及 root 唯一截图通道。该开关只改变 threaded animation；GPU compositing 的开关为独立设置，见 [Chromium 154 renderer 初始化源码](https://raw.githubusercontent.com/chromium/chromium/154.0.8037.98/content/renderer/render_thread_impl.cc)。采样前后动画状态及 CSS／rAF 帧率、CPU、输入响应和同帧几何分别验收。

传输方案依据多页冷启动测量确定，保留认证、Origin、项目／会话／view 归属、断线宽限、页面离开和资源清理。CEF 保持项目私有 profile、真正后台运行、renderer sandbox、私有剪贴板及既有 Keychain 策略。

## 验收与交付

隔离测试使用与实际项目接近的素材尺寸、对象数和 HTML 数量，分别记录单页／多页冷启动、暖启动／刷新、HTML 点击及连续输入、普通滑动／缩放、两个音频布局和视频分别播放时的输入至真实呈现延迟，HTML 保持活动。视频记录原生解码帧和呈现时间，音频记录实际播放；静止平移的结果与播放场景分开。实际素材尚未由非内容接口暴露的时长与 codec 保持未知，合成 fixture 的这些字段单列。

前后测量采用相同环境和 fixture，保留失败运行及最终重复，原始数据归档到 `docs/evidence/interactive-media-performance/`。执行者完成实现与测试，独立审查者验收当前代码、证据和声明范围；主智能体形成最终文档、受控运行更新和 Git 提交。正式更新前后经业务接口比较任务、草稿、对象、批注、视口及原素材字节；测试始终使用独立项目。

输入延迟的测量终点为主线程成功写入可见 Canvas 后的提交，按该次 camera／对象位置对应输入；浏览器与系统 compositor 的屏幕输出延迟单独保留为测量范围外。
