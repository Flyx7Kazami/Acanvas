# 对象与内容的统一回退历史

- 日期：2026-10-13（Asia/Shanghai）。
- 阶段：P2，R14 / A15 的验收扩展。
- 状态：实现、独立验收与当前验收服务更新完成。

## 产品范围

白板对象的所有持久修改进入同一条 Undo/Redo 历史，包括新增、删除、位置、尺寸、对齐、颜色，以及当前产品提供的便签正文和 Markdown 源码编辑。正文修改、对象移动、再次修改正文、删除对象，可以依次回退与前进。刷新、服务重启及退出编辑后仍可恢复正文。

已有对象以更新时的已保存正文作为内容历史起点，后续编辑进入统一历史；已有对象属性历史继续保留。

便签与 Markdown 编辑器中的 Cmd/Ctrl+Z、Cmd/Ctrl+Shift+Z、Ctrl+Y 统一操作白板历史。聊天输入和批注草稿继续使用自己的编辑历史。文字编辑按连续输入段落合并，停顿或结束编辑形成一个步骤；输入法组合期间保持组合完整。点击 Undo 或按快捷键时，先保存尚未提交的这一段，再撤销正文步骤。

用户已确认历史只负责白板保存的状态。平移、缩放视图、选择、媒体播放，以及嵌入 HTML 的表单与脚本状态继续作为视图和运行交互。

## 统一数据与执行链

正文编辑使用对象内容操作 `{ type: 'content', objectId, expectedVersion, text }`，通过现有 `board operations` HTTP/CLI 业务接口提交。对象 ID、布局、颜色和来源保持；服务保存新的素材内容，并让对象引用这一份素材。各次正文内容保存为独立素材，保留旧字节，现有对象前后快照即可表达内容回退。已发送任务、截图和早先引用继续读取各自的素材。共享同一原素材的另一个对象保持自己的内容。

对象内容变化沿用对象版本、短事务和 session 历史；同对象外部修改触发冲突。内容大小沿用 UTF-8 2 MiB 上限，JSON 传输需要容纳有效文字的转义。相同正文是空操作。文件准备失败、校验失败或事务失败保持对象与历史位置，临时文件按明确归属清理。素材原字节经只读接口读取，编辑统一经对象业务操作提交。

普通对象写入、正文保存、Undo 和 Redo 共享页面内按 session 的串行执行链。操作前收束尚未保存的编辑；同一页面已确认的正文保存可为紧随其后的布局操作衔接对象版本，外部版本继续由服务校验。内容恢复后编辑器同步到恢复值，保持焦点、光标与输入法规则，迟到的读取或保存完成不会将已撤销正文重新写回。

对象内容编辑器向页面登记待保存状态与 flush 能力，使按钮、快捷键、移动、颜色、删除、切换任务范围和页面关闭都使用同一保存语义。历史回放触发的编辑器更新只同步显示。历史任务中的素材预览使用只读内容。

## 验收

1. 便签 A→B→C 连续撤销/重做，使用工具栏及编辑器快捷键；空正文、Unicode、换行及输入法组合保持。
2. 内容→移动/缩放/颜色→内容→删除混合操作按时间顺序恢复；恢复同一对象与对应正文。
3. 自动保存前立即 Undo、保存请求延迟时立即 Undo、快速继续输入以及 Undo 后新输入都保持内容与历史顺序。
4. Markdown 源码编辑与预览更新、切换预览、刷新与服务重启后 Undo/Redo 正确。
5. 两个对象引用同一原素材、已发送任务快照、两个 session 竞争、同一对象的外部内容修改都保留正确归属与冲突边界。
6. 内容空操作、2 MiB 边界、失败保存、多对象原子操作与已有历史回归通过。
7. 聊天/批注编辑、HTML 当前交互及移动/缩放/颜色原有用例保持，完成独立干净上下文审查。
