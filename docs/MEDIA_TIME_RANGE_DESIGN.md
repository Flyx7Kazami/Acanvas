# 音视频批注时间范围选择

日期：2026-10-06。阶段：本轮实施设计。关联 R04、R05 / A06、A07。

## 目标

用户在音频或视频批注中直接沿媒体时间轴框选时间，而非切换目标下拉框或填写终点数字。参考图中的核心结构是连续内容轨道、选中范围、两侧拖动柄和起止时间。批注只记录时间引用；界面没有剪切动作或剪刀图标。

## 界面与操作

- 编辑单个视频或音频的批注时，在评论区内显示一条紧凑时间轴。视频轨道展示从原文件取样的真实帧；音频轨道复用完整音频的振幅波形。预览尚未就绪时使用平静的轨道，选择操作仍可用。界面沿用画板现有灰度、圆角与字体，选中框和左右端点是唯一强调元素。
- 选中范围是**一个矩形**：两侧各约 8px 的白色侧轨内嵌窄深色握柄，顶部和底部各有与侧轨连成一体的细白边，形成单一白色圆角框；不画额外深色外框。可触摸的命中区比可见握柄大，位置仍对应准确起止值。轨道使用浅灰底与中深灰波形；选区内保持近透明的浅色薄纱，选区外叠约 58% 的黑色遮罩。遮罩沿选区矩形自身的圆角外缘生成，与选区共用几何边界，避免左右独立遮罩在圆角处留下缝隙。两种主题使用同一套灰阶，批注蓝仅作为键盘焦点色。用户提供的图 2 是**中间局部选区的外观参照**；新建批注仍按下条要求默认全段。左右端点分别设置 start 和 end，拖动时显示对应时码。点按轨道设置单个时点；在轨道空白处拖动可框选区间。单时点的起止值相等时选区宽度为零，只显示位于真实时间点的窄标记；左右端点仍有分别可操作的命中区，拖开后成为区间。起止值不同但换算为屏幕像素后短于两侧轨所需空间时，选区按真实时间跨度收紧为简洁的短区间形态，避免两组白轨与握柄重叠；起点、终点的指针/触屏命中区仍各自独立。没有额外的 cut 控件。轨道高 26px、整块时间控件约 57px，批注卡片保持紧凑。
- 每次新建视频或音频批注均从 `0…duration` 的全幅选择开始，不继承媒体此前的播放头或上一次批注的选区。拖动端点或框选后保存明确时间；重新打开已有草稿批注时按其已存起止时间恢复，不覆盖用户已提交的选择。音频全幅沿用整段语义（`timeStart`、`timeEnd` 均为空）；视频已有时长时全幅保存 `0…duration`，时长尚未就绪时先用双空表示整段，时长可用后由界面补齐全幅——该补齐只作用于本次新建的视频批注，重新打开的历史批注不会被改成整段。端点始终在时长内，起点不晚于终点。
- 两个端点可通过键盘聚焦及方向键移动，并向读屏器报告端点与时码；触屏有可命中的手柄。媒体时长尚未就绪时保留原批注值，时长可用后启用选择。只读任务快照继续显示时码与显式 Jump 操作。
- 时间轴旁提供节选播放/暂停按钮。按下后从选区起点播放原媒体，到选区终点自动暂停；单时点选择播放起点后的短片段，受媒体尾部限制。播放期间可手动暂停；改变选区或关闭批注会结束本次节选试听。按钮状态与失败反馈清楚，键盘和触屏可操作。调整批注范围本身不改变画板中媒体的播放位置。
- 视频代表帧应对应最终起点；若当前浏览器无法取得该帧，保存起止时间并显示现有帧不可用状态。拖动中只更新界面预览，松开后提交草稿变更，避免每个指针移动都写入草稿。

## 数据与验收

继续使用 `AnnotationInput.timeStart`、`timeEnd` 与现有草稿和任务快照接口。移除编辑态的音频目标下拉框及 End time 数字输入，不改已发送任务的数据结构。测试使用独立临时项目和媒体，覆盖视频与音频的整段、时点、短区间、普通区间、端点拖动、框选、键盘、触屏、节选播放与自动暂停、草稿恢复与发送后快照；视频帧关联与最终起点一致。外观验收以真实浏览器截图为准：上下白边和两侧窄白轨连续，遮罩贴合圆角边界；当起止值相等时显示窄标记，当短区间不为零时保留与时间跨度对应的紧凑形态，不出现重叠白轨；两端都可再独立拖开。选区内外的波形保持清楚明暗，浅深主题保持同一层次。验证窄屏批注卡片、缺少媒体时长及异常预览；真实项目仅进行只读页面核对。
