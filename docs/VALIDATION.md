## 功能与回归覆盖

- 全宽项目画布、底部居中输入框、上方任务条；界面移除独立会话创建和切换。
- 输入框自身没有 focus outline、border、shadow 或背景 highlight；其余按钮、对话框与任务操作保留焦点反馈。
- 队列 1–3 项标题可读，超过 3 项呈现叠层/数量并向上展开；hover bridge、滚动、鼠标一次收起、Enter/Space、触屏及详情焦点恢复通过。
- files/items 统一提取；画布点击正确聚焦；document 单入口按目标把文件送入画布或附件，普通文字编辑保留，离线导入给出错误。
- 独立 PNG 键盘及合成 paste/drop 测试验证焦点和路由；这些测试不替代 Finder 原生文件传输矩阵。
- host/thread 映射同对话复用、不同对话隔离；旧绑定 URL/任务保留；无绑定链接的独立标签页保持各自任务范围。
- 委派执行使用父对话或明确链接；已实测子 agent 的环境线程身份与根对话不同，Skill 据此明确绑定优先级。
- detached 服务在启动命令退出后仍存活，status/stop 核对项目与服务实例；重复启动保护、任务与资产重启持久化通过。
- 既有草稿 CAS、发送幂等、快照、产物归属、任务/consumer 生命周期、对象原子更新、安全边界及服务重连回归继续通过。
- 不同项目的写入阻断允许在请求前完成，或最多一次失败请求后停止；成功写入为零，目标项目数据保持原样。

## Finder 验证证据与限制

用户说明故障来源是在 Finder 中复制图片、视频或文件。实际故障检查确认旧服务已停止，且旧画布点击未正确转移焦点；两项均已修正。

新版正式页面打开后，用户从 Finder 复制测试文件并在画布按 ⌘V，明确回复“可以粘贴了”。只读检查确认正式项目的对象由 2 个增加为 4 个，新增图片和视频仍可见，现有对象保留。

原生自动化尝试使用隔离项目及 opt-in 测试 helper。helper 完整快照 item/type/data 到内存，在私有 pasteboard 核验恢复等价；任一内容无法完整保存即在写入前中止，恢复时检查 changeCount。成功进入保护窗口的那一次，最终原剪贴板的 item、类型和 flavor 字节已在内存确认等价恢复。

CUA 浏览器键盘走虚拟剪贴板，未发出读取系统原生文件剪贴板的粘贴；计算机使用工具也禁止控制 Codex 原生窗口。因此该尝试没有形成自动化 Finder 通过证据。后续额外原生测试已停止，用户当前剪贴板继续由用户控制。生产功能使用浏览器 File 数据，没有新增从粘贴文本读取任意磁盘路径的接口。

## 测试过程中的保留事项

一次临时 native fixture 目录清理发生得过早：该目录后来出现了一个来源未核实的导入副本，在保留指令到达前已被清理，现已无法继续辨认其来源。没有将此项记为恢复成功或 Finder 自动化通过。正式 `4317` 项目未参与该清理，后续只读核对显示其新增素材仍在。

项目协作规则已补充：清理前核对测试内容归属；出现未知或用户加入内容时先保留现场再决定处理。后续自动化继续采用独立项目。
