# 画布操作性能优化

日期：2026-10-14（Asia/Shanghai）。分支：`codex/performance-smoothness`。起点：`7165e91`，开始时已同步远端主线。

## 需求与范围

用户反馈拖动、平移、缩放及其他画布操作偶尔卡顿，要求全部现有功能、操作与特性严格保持。工作对应 P0/P2，覆盖 R03–R05、R08、R14、R15 / A04–A07、A11、A15、A16 的既有行为；安全与生命周期继续遵循 A14。

本轮通过隔离项目测量当前 DOM 画布，定位高频路径中的重复派生计算、布局读写和 HTML 预览通知。性能判断使用同一 fixture、浏览器、视口、DPR 和操作序列的前后结果，保留原始样本及失败运行。旧的持续 Canvas 显示性能脚本与当前 DOM 显示路径不同，本轮另行记录实际输入至 DOM 几何更新的口径。

## 设计约束

- 保持每次有效输入的几何结果、首帧响应与手势结束时的保存；沿用合帧、吸附、Alt 绕过、指针取消和缩放上下限。
- 派生数组按真实输入复用，索引仅用于查找；显示顺序、当前对象版本、历史来源及 snapshot 素材优先级沿用现有规则。
- HTML 预览继续响应全部可见性、尺寸、交互和生命周期变化；只有对外状态实际变化才触发订阅通知。保留名额、缓存、截图交接、请求优先级和取消后的迟到 grant 回收。
- 浮层保持同次布局完成定位，继续响应画布、控件及障碍物尺寸变化；通过稳定观察器和相同值写入去重减少重复布局，摆放算法、测量顺序与命中范围保持。
- 服务写入、事务、版本冲突、历史、任务范围与截图来源机制保持现有规则。测试使用独立临时数据与本工作树构建，正式白板与运行服务继续使用现有版本。

## 热点与实现

`useContextualControls` 原本在每次 React 提交时创建 ResizeObserver，并重新订阅画布、控件和障碍物。一次 60 步平移的初次诊断出现约 63 次新建；5/15 条批注时布局读取累计约 6,605/21,869 次。当前复用一个观察器，按实际 DOM 集合差量订阅，每次提交继续同步定位；相同属性与样式值保持原值。

`App` 原本随相机变化重新派生对象、组成员、素材和选择列表，并在每个对象渲染时扫描当前对象与外围成员。当前按实际输入复用派生数据，使用独立索引查找 displayed/current 对象及素材；数组输出顺序、首次匹配和 snapshot 素材优先级保持。`@` 搜索打开时才构造候选，原候选排序和筛选继续执行。

`HtmlPreviewPool` 监听祖先 style 等属性变化，画布 transform 每次变化都会同步协调预览并无条件发布。当前继续处理全部事件，一次协调内复用可见性读数，比较各预览对外的 slot、image、width、height、generation，实际变化时发布。13 个冻结预览、120 次 transform 的直接池测量中，无效通知从 120 次降为 0；直接协调耗时约 8.9→14.1ms，增加约 0.043ms/次。此测量排除了下游 React 渲染，整体性能以真实 App 对照另列。

## 画布性能实测

Chrome 155.0.8059.40、1440×1000、DPR2、12 个对象，原版/候选各两轮交错运行。对象采用固定 ID、位置和创建/显示顺序，拖动统一选择 `perf-object-00`（Image 0，70/100、250×160）。场景分别为 0/5/15 条批注和 5 条批注加持续播放视频；每场景测 60 步拖动、60 步选中平移、40 步缩放、60 步空选区平移。输入来自真实 pointer/wheel，响应终点为 RAF 首次观察到准确 DOM 几何，屏幕合成器展示延迟在范围外。CDP 脚本/布局耗时覆盖操作与 150ms 收尾时窗，输入至 DOM 分位数单独统计。

独立审查发现早期脚本通过 DOM first 选择拖动目标，同批创建对象的随机 ID 排序使四轮实际目标位于不同网格位置。原始样本及原百分比留在 `exploratory-summary.json`，最终数据采用固定 ID/层序后的八轮。独立审查核对四轮画布 fixture、初始几何、每阶段最终 DOM 几何一致。

固定场景的两轮均值，耗时单位 ms；p95 保留逐轮值：

| 15 条批注操作 | 原版脚本耗时 | 当前脚本耗时 | 变化 | 原版响应 p95 | 当前响应 p95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 拖动 | 258.05 | 171.31 | −33.6% | 17.2 / 18.6 | 18.2 / 17.8 |
| 选中平移 | 1,524.01 | 1,464.89 | −3.9% | 25.1 / 24.7 | 25.0 / 31.2 |
| 缩放 | 737.27 | 738.31 | +0.1% | 25.7 / 24.9 | 24.3 / 31.0 |
| 空选区平移 | 1,067.03 | 1,065.18 | −0.2% | 21.3 / 21.4 | 21.3 / 24.3 |

5 条批注的拖动/选中平移/缩放脚本耗时分别减少约 22.2%/15.4%/16.3%；持续播放视频时分别减少约 16.8%/10.7%/12.1%。无批注的对应三项减少约 7.8%/7.6%/10.3%，每阶段原 67/63/41 次观察器新建变为 0。小幅回退保留：无批注空选区平移平均 p95 增加 0.25ms，无批注缩放布局耗时增加约 4.2%，5 条批注缩放平均 p95 增加 0.1ms。高批注的第二轮候选平移/缩放尾延迟明显增加，缩放出现一条 52ms 长任务及 53.7ms 最大输入延迟，原样本继续保留。

四轮共 3,520 次输入，3,504 次准确匹配、16 次中间位置由既有合帧机制替代、pending 为零；64 个阶段的末输入和保存一致，16 个场景的取消回滚与刷新一致。页面异常均为零；视频每阶段保持 ready/playing 且累计解码帧增长。取消检查使用真实拖动后合成 pointercancel；物理触控板、其他浏览器及真实用户素材的最坏负载属于后续验证范围。

完整可重算样本、逐轮分位数、计时口径与中间失败保留在[结果摘要](evidence/performance-smoothness-20261014/summary.json)及同目录 `canvas-fixed-*.json.gz`。所有长任务按开始时间归属阶段；此前探索样本的范围与修订见同目录 README。

追加 15 条批注聚焦原版/候选各两轮，另两轮 trace/1ms CPU profile 独立诊断。聚焦四轮均无长任务，拖动/平移/缩放脚本耗时减少约 33.6%/7.7%/8.8%；p95 逐轮为拖动 18.2/17.8→18.5/18.7ms、平移 24.0/23.8→23.9/24.6ms、缩放 25.0/23.5→22.4/23.0ms。原 52ms 样本缺少调用栈，后续诊断未复现，确切原因保持未知。源码映射显示两版共同热点在 `placePointAnnotationNote` 候选/碰撞/评分排序；该诊断阶段 CDP 脚本约 1,460/1,362ms、布局均约 19.5ms。平移中该模块占已映射 `src/web` 样本 725/916（79.1%）与 725/858（84.5%），program/idle/GC 单列，比例属于源码样本而非总 CPU。CPU profile 原始 timeDeltas 含负值（672/578 条），直接加权曾得到负来源耗时；修正分析按累计 timestamp 排序重建非负相邻区间并按阶段裁切，原始数据继续保留，正文采用调用栈/样本定位。两版均有较短 GC 样本，现证据无法将原 52ms 归因于 GC。诊断采样开销单列，数值留在[聚焦结果](evidence/performance-smoothness-20261014/focused-summary.json)和[诊断结果](evidence/performance-smoothness-20261014/diagnostic-summary.json)。

## 文件夹操作补充

主智能体通过真实内置浏览器在独立白板验证：文件夹进入、正文编辑、返回、正文 Undo、原位改名、整体选择形成一个 group 引用、展开、重新收纳、直接解组、解组 Undo 和刷新。再次进入/返回后，父视口 transform 与进入前逐字一致；连续 Zoom out 实际到 5% 且 camera scale 精确为 0.05，随后恢复 Fit。截图及读回见[实测页面](evidence/performance-smoothness-20261014/manual-folder.jpg)和[操作记录](evidence/performance-smoothness-20261014/manual-folder.json)。

独立审查者已通过六项分组/文件夹真实 UI 用例，涵盖 caption 拖动、hover/focus、二级移动/新增便签/导入/批注、精确父视口恢复、390px 暗色和减少动态效果、收起动画中的接管及 Done 像素、分组引用和正文历史。

固定五对象 fixture（3 成员含便签、右侧和下方邻居）以原版/候选各两轮运行，每轮 16 项操作，共 64 步。包括收起及 Undo/Redo、整体拖动、进入、组内移动及 Undo/Redo、正文编辑及 Undo/Redo、返回、展开、直接解组及 Undo/Redo。原 420ms 动画和 620ms 生命周期自然完成。每步通过独立 HTTP 来源常量检查完整批注来源保持，核对成员/邻居/正文与历史；跨四轮 fixture、19 个业务快照及最终 DOM 几何一致，CSS 序列化最大差约 0.000333px。

| 操作 | 原版脚本耗时均值 | 当前脚本耗时均值 | 变化 |
| --- | ---: | ---: | ---: |
| 文件夹整体拖动 | 47.28ms | 38.95ms | −17.6% |
| 进入二级画板 | 37.56ms | 32.48ms | −13.5% |
| 组内移动 | 44.65ms | 36.53ms | −18.2% |

64 步长任务为零，帧间隔 p95 约 16.7–16.8ms。墙钟回退单列：整体拖动首反馈约 47.6→66ms，candidate 第二次实际 move 比原版晚一帧；触发拖动阈值的 move 至反馈为原版 15.5/17.0ms、候选 16.8/16.7ms，末输入至终态约 252–254ms 保持。组内移动一轮手势输入本身为 726.8ms、其余约 512–531ms，终态均值因此增加约 100ms；末输入至终态约 35–39ms。正文 Undo 终态约 29.5→39.9ms、重做解组脚本增加约 3.2%，原始样本全部保留。CDP 操作时窗也包含 Alt/定位与输入发送；逐 move 的显示匹配未逐一断言，末位置与输入数量均核对。

完整数据见[文件夹结果](evidence/performance-smoothness-20261014/folder-summary.json)、`folder-fixed-*.json.gz` 与三类实际截图。独立审查进一步核对归档的 `annotation-source.json`：target、sceneSource、版本、session/draft/capture 归属一致；四张原批注 PNG 均为 584×488、22,228 字节，逐字节相同。对象移动和便签换新素材后，批注继续保留原位置和原正文素材来源。

## 后续空间

多条批注仍是较大的同步开销：`CanvasAnnotationNote` 随 view 变化测量并定位，`placePointAnnotationNote` 生成候选后反复评分排序。固定两轮候选 15 条批注选中平移约 23–25ms/输入脚本工作，聚焦 profile 也确认该 JS 热点。后续可独立验证评分复用和测量批次，同时保持摆放、遮挡、动画及截图规则。当前结果支持已测重复工作减少，偶发尾延迟继续作为开放的性能边界。
