# acanvas 前端设计

更新日期：2026-10-01。

## 视觉依据

采用灰、黑、白主配色，沿用相邻 `giga_components` 的字体、留白、控件尺度、圆角及轻量动效。素材保持其原始色彩。用户提供的两张输入区参考图确定底部输入框与上方任务条的关系。

## 项目画布

画布占据主体空间，顶部呈现项目、保存状态、导入与主题。画布上的素材和布局由项目共享；工具条避开底部输入区。白板界面提供项目与任务，不呈现独立的会话创建、切换或侧栏。任务归属由宿主 agent 对话绑定，内部标识用于持久化和准确路由。

## 输入区与队列

输入框浮动于正下方居中，附件位于框内，文字区下方保留添加与发送操作。输入时 textarea 的背景、边框、outline 和阴影保持透明或无；按钮、任务操作和对话框保留清晰键盘焦点。

队列贴着输入框上沿并略微内缩。1–3 条任务的标题均可读；超过 3 条显示叠层及数量，悬停向上展开更多任务，输入框位置保持稳定。展开列表有高度上限和滚动，鼠标经过两者之间保持连续。键盘和触屏有等效展开入口。

展开与收起采用同一可见状态：一次点击即可收起，当前悬停或焦点保持时维持用户的收起决定，离开后再次进入可重新展开。任务详情关闭后恢复正确焦点；记录入口保留回执和已完成内容。

## 粘贴与导入

统一 document 粘贴入口读取浏览器提供的 files/items。画布、空白区域或普通按钮上的文件粘贴进入共享画布；输入框内进入当前需求附件。点击画布主动聚焦，普通文本编辑保持原生行为，服务离线或文件无法处理时提供明确反馈。

Finder 原生文件粘贴的当前证据为用户在真实内置浏览器手工确认；合成事件与 PNG 自动化分别记录其验证范围。生产导入通过浏览器 File 数据，不从粘贴文本推断任意本地路径。

## 验证

检查亮/暗主题、窄屏、输入时无 highlight、队列 1/3/6 项、hover bridge、一次收起、键盘/触屏、详情焦点恢复及 reduced motion。所有自动化使用隔离项目，真实用户项目保留原有素材和草稿。
