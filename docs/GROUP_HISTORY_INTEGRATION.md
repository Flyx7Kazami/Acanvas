## 业务规则

一次成功的白板事务形成一步历史。分组创建、改名、整体移动、收纳、展开和解组，与成员新增、删除、转组、几何及正文编辑共用历史。收纳或展开引起的邻居位移属于同一步。Undo/Redo 恢复组身份、名称、颜色、模式、锚点、成员归属、内部布局及受影响邻居；组和对象的版本继续递增。

组属于项目，历史属于项目内的任务范围。其他范围对独立对象和组的修改保持；该步涉及的对象或组已由其他范围修改时，整步返回 409，历史位置保持。失败事务和无变化操作保持历史。Undo 后提交新操作结束当前范围的 Redo 分支。

便签与 Markdown 使用不可变素材版本，保留旧字节及任务引用。已发送的 group 引用保留发送时的组、成员、素材和布局；新增显式 item 引用读取当前内容。视口、选择、聊天草稿、队列状态及嵌入 HTML 的运行状态沿用各自管理方式。

## 持久化与执行顺序

服务在同一短事务内读取完整白板前后状态，再提取实际变化的对象与组。历史保存 `{objects, groups}` 两个按主键索引的集合，删除使用空值；保存的实体范围覆盖业务操作的实际写集。历史回放仅修改该步集合中的实体。

既有对象历史在数据库初始化事务中转换为同一结构，保留历史行、游标及对象 lineage。对象沿用既有版本计数与历史 head；组使用独立的版本计数及历史 head 表。计数在实体删除后保留，恢复时分配新版本，旧 expectedVersion 继续触发冲突。恢复先建立组，再恢复对象及 groupId，最后删除已清空的组，以维持外键约束。

UI、CLI 与 task complete 使用同一业务操作。操作、Undo 和 Redo 的响应均携带 `objects`、`groups`、`history` 及本次事务的 `versionChanges`。后者分别列出对象和组的真实前后版本，覆盖邻居位移、删除与恢复。内容生成文件与对象、历史、产物及回执在同一提交链路中处理，事务失败清理本次生成文件。

前端按 session 串行执行普通操作、内容保存和历史回放。同一页面前序操作返回的连续版本变化可供后序操作使用；仅当 expectedVersion 属于该页面自己的连续链时更新它，外部版本间隔继续触发 CAS。实际呈现场景的组位置、过渡、虚化和缩放与当前正文身份一起进入 Done 截图。左侧工具栏、图标、单 group 引用、二级磨砂与队列完成动效保持既有产品规则。

## 验收范围

1. 组创建、改名、移动、收纳、展开、解组逐步 Undo/Redo；邻组与散落 item 的实际位移整步恢复。
2. 成员新增、删除、转入、跨组和回到一级恢复身份与归属；组内 note/Markdown 正文与布局交错回放，重复正文保持无操作。
3. 刷新和服务重启保留历史；既有对象历史继续回放；删除、恢复后旧版本写入冲突。
4. 独立范围修改保持，同实体竞争原子 409；失败批次保持对象、组、历史、编号及素材一致。
5. 发送 group 引用后编辑正文、改名、解组，历史引用仍保留原来源；显式 item 引用使用当前来源。
6. 浏览器实际执行分组与二级内容历史、快速连续操作、磨砂与 Done、队列完成及窄屏工具栏；类型检查、生产构建与相关服务回归通过。
