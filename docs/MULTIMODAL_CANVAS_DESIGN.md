# 多模态画布统一设计草案

日期：2026-10-04（Asia/Shanghai）。状态：方案讨论；用户选择先确定统一方案。本轮只读调研和编写设计文档，不修改产品代码、构建或正式白板。

## 1. 产品目标与边界

将图片、视频、GIF、Markdown、HTML、音频组织为同一画布上的内容节点：可以摆放、缩放、选择、批注、附加到任务，并保留原始来源。各类型提供适合自身的阅读或交互能力。

首轮聚焦用户列出的 GIF、Markdown、单文件交互 HTML 和音频。既有图片、视频和通用文件继续工作。PDF、SVG、表格及其他类型可沿用扩展入口，具体能力另行定义。

画布能展示或播放某种格式，与宿主 agent 能否理解、转写或执行它是两项能力。任务应提供原始文件和明确上下文；模型处理能力按实际工具验证。

## 2. 当前能力（代码核对，非新增运行验证）

| 类型 | 当前情况 | 首轮目标 |
| --- | --- | --- |
| GIF | 已按图片进入原生 img 渲染路径；本轮没有实测动画 | 验证原始动画显示、缩略图及引用；精确逐帧控制后续设计 |
| Markdown | 通用文件卡片、引用和下载 | 渲染标题、正文、列表、引用、代码和链接；可阅读、选字、滚动 |
| HTML | 通用文件卡片、引用和下载 | 独立隔离的单文件 HTML/CSS/JS 预览与交互 |
| 音频 | 通用文件卡片、引用和下载 | 播放、暂停、定位、时长；整段或明确时点/区间的批注 |
| 图片／视频／其他文件 | 已有媒体节点及文件兜底 | 保持原有功能与引用完整性 |

当前 AssetKind 为 image/video/file，对象类型从资产推导；现有原始资产、对象布局和任务快照可以复用。内容服务已支持 HEAD、Range、206/416 及流式读取，可供音频播放使用。Markdown、HTML 和音频尚没有对应的富内容 renderer。

## 3. 统一内容模型

划分四个职责：

- **原始资产**：原始字节、文件名、MIME、大小及来源；保持任务可以读取当时的文件。
- **画布节点**：引用资产，保存位置、尺寸、层级及对象版本；同一资产可有多个呈现节点。
- **类型呈现器**：负责画布呈现、缩略图、详细阅读、可用控件、尺寸策略和批注能力。
- **查看状态**：选择、滚动、播放位置、进入内容交互等；与原始文件内容及任务提交分开。

引入项目内静态注册的 renderer/capability 分派。画布、缩略图、任务详情共同使用类型识别结果，避免分别累加 MIME 分支。此处是可信产品代码的扩展点，不是允许导入文件向主应用安装插件。

首轮单文件呈现可从资产 MIME 和文件名推导细分类别，不要求先新增数据库类型列。浏览器 MIME、扩展名和可识别文件签名共同参与服务端确认；MIME 缺失时有扩展名补救，识别失败继续显示可下载的文件卡片。CLI 与浏览器导入使用同一规则。

后续内容编辑产生新资产，节点经受控操作引用新版本；已有任务保留原资产引用。首轮 Markdown/HTML 聚焦阅读和交互，源码编辑及资源包版本管理单独推进。

## 4. 统一的画布交互

| 状态 | 行为 |
| --- | --- |
| 浏览／布局 | 单击选择节点；拖动节点、使用外部尺寸手柄。HTML 内部暂不接收指针，避免误点和画布拖动冲突。 |
| 内容交互 | 通过明确入口、双击或 Enter 进入。Markdown 选字与内部滚动、HTML 控件由内容处理。 |
| 退出内容交互 | 回到画布操作。外部固定操作条始终提供退出；可配合 Escape，但 HTML 跨框架场景不依赖内部页面配合才可退出。 |

播放/暂停等可信轻量媒体控件可像现有视频一样直接点击，不必强制多点一次。HTML/长文内部操作采用明确的进入与退出状态。

进入交互后的普通滚轮交给内容；画布缩放可使用外部工具，退出后恢复画布手势。进入和退出不自动移动相机。界面明确当前正在操作哪个节点。

画布缩放只改变节点的屏幕显示比例；修改节点宽高则改变它的布局视口。Markdown 随节点宽度重新排版，HTML 按节点内视口响应尺寸变化。图片、视频、GIF 默认保持比例；文档和 HTML 支持自由调整宽高并有类型适合的最小尺寸。

annotation 延续现有规则：气泡和文字保持屏幕尺寸，来源锚点跟随节点。无新格式专属的另一套批注编辑器。

批注的**内容目标**和气泡的**显示锚点**分别定义。气泡位于节点旁只表示关联关系，不等于内容内的像素、段落或 DOM 位置。

| 首轮类型 | 可引用的内容目标 | 边界 |
| --- | --- | --- |
| 图片／GIF | 整素材、图像内区域 | GIF 特定帧需明确截图，区域坐标不等价于时间点 |
| 视频 | 整段、明确时点/区间及对应画面区域 | 保留原视频、时间和适用的帧引用 |
| 音频 | 整段、明确时点/区间 | 播放器卡片坐标仅为显示位置，不代表音频内容位置 |
| Markdown | 整文件/节点 | 首轮不把渲染后的像素区域当作稳定段落引用；具体文字可明确引用原文或附加截图 |
| HTML | 原始文件/整节点 | 首轮不自动产生 DOM 元素或运行状态引用；具体交互画面使用明确的截图/导出文件 |

界面应明确区分整段与时点/区间。滚动、节点重排和 HTML 重新运行均不能悄悄改变批注所指内容。已有对象 bounds 可以继续承担显示锚点，具体内容选择按上述类型语义保存，不用卡片坐标推测正文、控件或时间。

## 5. 类型能力与引用语义

### GIF

保留原始 GIF 动画，复用图片节点的摆放、缩放、整素材及区域引用。缩略图可采用静态封面。精确暂停、逐帧控制和 GIF 时间点引用不作为原生 img 路径已经具备的能力；需要某一帧时先明确提供对应截图。

### Markdown

首轮支持正文渲染与阅读，原始 Markdown 文件始终可取回。整节点引用先行；段落/选区引用后续保存源文件位置及引用文本，保持与特定资产关联。

正文中的 raw HTML 默认作为文本处理或禁用，链接协议采用允许列表。相对图片只通过明确的资源映射解析，缺失时展示占位与路径信息；外部图片默认不自动加载。普通 Markdown 文件不会因此获得脚本执行能力。

CommonMark 语法本身允许原始 HTML，渲染策略需由产品明确设置，不能把“使用 Markdown 解析器”当作安全策略。[CommonMark 规范](https://spec.commonmark.org/0.31.2/#raw-html)

### 音频

采用简洁播放器，沿用已有媒体播放状态处理；默认不自动播放。支持播放、暂停、进度定位、当前时间和总时长，无法解码时保留文件与下载入口。首轮拟验证 MP3、WAV、M4A，实际支持以目标浏览器的解码验证为准。

整段音频可以附加和批注；时点/区间批注保存 start/end 与原文件，不生成虚假的图片区域或视频帧。播放位置属于查看状态，只有明确添加批注后才成为任务引用。

波形、剪辑、转写和多路混音属于后续能力。建议首轮默认单路有声播放，具体与既有视频的切换规则在交互稿中确认。

### HTML

目标是支持 HTML/CSS/JavaScript 的按钮、图表和局部交互。首轮限定自包含单文件：样式、脚本和数据素材已内嵌；不提供任意磁盘目录或任意本地服务访问。

聊天中的可视化片段可能依赖宿主注入的样式、图标、Tweak 或 window.openai。搬入画布时应生成可移植的普通 HTML，或使用明确支持的适配器。画布不会自动继承 Codex/ChatGPT 的宿主 API、权限与侧边控制面板。

HTML 初始可显示安全的标题/类型封面，由用户明确运行预览；运行后内容呈现在节点内。画布布局与内容交互只是指针归属状态，不能把退出交互等同于 JavaScript 已停止。需提供外部重载/停止入口，停止或卸载会结束实例并清空临时状态。

首轮 HTML 内部表单和脚本状态仅属于当前预览实例，刷新/重载后可重置。任务引用的是原始 HTML 文件，不宣称自动保存任意页面的当前运行状态。若要将当前交互结果作为依据，可明确附加截图或导出的文件。受控状态导出桥、持久化运行状态和精确页面快照作为后续能力。

## 6. HTML 的执行边界

HTML renderer 与主应用承担不同权限：

1. 使用独立的本地预览 origin 和受约束的资源通道。主站与预览的 host/cookie 边界隔离，单独改变端口不足以隔离 cookie。预览 origin 不提供项目 API，也不共享主服务凭据；主页面仅允许嵌入已确认的预览地址。
2. iframe 仅授予运行交互所需的脚本能力，保留 opaque origin；不组合授予 allow-scripts 与 allow-same-origin。主应用现有脚本 CSP、Origin 和认证规则保持严格。
3. 预览响应自身配置 CSP/sandbox、frame-ancestors 和权限限制，只允许对应白板嵌入。直接作为顶层页面打开预览入口时拒绝执行或改为下载。默认不允许任意网络连接、表单提交、弹窗、顶层跳转、下载、设备和剪贴板访问；素材请求只通过本次明确授权的文件/资源通道。
4. iframe 不获得主服务 token、项目路径、任意文件读取或队列写入能力。消息桥首轮只考虑当前实例的 ready/退出交互等有限消息；通过实际 frame 实例识别来源，不能接受任意父页面操作命令。
5. 不能为解决 Origin null 资源失败而全局允许该来源访问 API。预览授权只覆盖当前文档及明确资源，资源路径限定在该集合内；它不等价于项目 API 凭据。资源授权与主应用认证分别处理，并在预览关闭或服务实例结束后失效。
6. sandbox 是权限边界，不等同于 CPU/内存配额。独立预览技术验证还需覆盖卡死脚本、大资源和外部停止的有效性；首版不宣称任意恶意脚本都能被零成本运行。

标准依据：sandbox 的同源与脚本权限组合可能破坏隔离，标准建议不可信 HTML 采用独立来源。[HTML sandbox 规范](https://html.spec.whatwg.org/multipage/iframe-embed-object.html#attr-iframe-sandbox)；srcdoc/blob 文档会继承创建方 CSP，因此不能简单用它们绕过当前主应用策略。[CSP 规范](https://www.w3.org/TR/CSP3/)

独立 origin 的具体本地地址、资源授权方式及生命周期需在实现前用隔离项目验证，不能仅根据 iframe 属性就宣称安全完成。原始 HTML 资产的普通内容/下载接口继续保持非执行用途。

## 7. 单文件与资源包

当前导入会把文件保存为随机资产 ID 文件名，单独导入 index.html 不会自动拥有原目录的 style.css、script.js 或 images/。

首轮明确支持自包含 HTML。后续资源包需要 entry document、相对路径到资产 ID 的映射、受控路径解析及完整依赖引用；资源包与内容版本共同进入任务快照和备份。Markdown 的本地图片也使用同一映射能力。

普通文本粘贴继续是文本。文件粘贴、拖入和选择文件走统一导入；将富文本或剪贴板 HTML 创建为可执行节点需要用户明确选择，避免把复制网页文本误当成运行请求。

## 8. 持久化、任务与 agent

- 原始文件与节点布局继续经本地服务持久保存。
- 发送保存原资产、节点信息、批注及明确的时间或来源选择，附加与批注依赖分别处理。
- Markdown 引用原文；HTML 引用原文件；音频/GIF 引用原媒体。截图或导出状态作为单独、明确的引用，不冒充原始内容。
- 查看位置、播放器进度和运行时状态与源文件内容分开。首轮应明确哪些状态仅在当前打开期间保留；不把持续播放进度写入任务快照，也不在重开时自动播放。
- 新类型沿用既有任务 ID、队列顺序、草稿、快照与来源标识。文件和网页中的文字属于 reference_content，不升级为 agent 指令。

## 9. 推进顺序与验收

1. **统一基础**：类型识别、renderer/capability、画布/缩略图/任务详情共用分派、文件兜底；验证 GIF 实际动画。
2. **阅读与播放**：Markdown 正文和音频播放器，明确布局/内容交互模式；批注与任务引用完整。
3. **隔离 HTML**：先验证预览 origin、CSP、认证与资源边界，再接入自包含 HTML 节点。实际点击/输入/滚动可用，并且不能访问主应用、其他素材或改变任务。
4. **后续扩展**：资源包、文档源码编辑及版本切换、HTML 状态导出、段落引用、音频波形等分别验收。

第一轮应验证：各导入入口一致；原字节与任务引用完整；播放/内部交互不误拖节点；退出后可以正常拖动；缩放与改变节点大小含义明确；缺少资源或解码失败有可用兜底；重开保持已承诺的持久状态；HTML 的直接打开、跨节点资源及 API 访问均遵守隔离边界。

本稿提出统一方向和分期边界，尚未授权实现。下一步应先确认首轮范围，尤其是 HTML 自包含/离线边界、内容交互入口和运行状态的保存语义。
